# “手动排除作品”功能

我要为下载器添加“手动排除作品”功能，需要为它新建一个模块。

功能说明：
用户点击按钮之后进入手动排除作品模式，显示指示器。之后点击任意作品元素即可把它加入排除列表，并在它上面显示一个已排除的标记。

---

## 一、设计决策（已与用户确认）

| 项目 | 决策 | 说明 |
| --- | --- | --- |
| 架构 | **完整父模块方案** | 新建共享模块 `WorkSelection.ts`，集中保存“手动选择作品”和“手动排除作品”两个功能的状态与 id 列表，并承担互斥 / 交叉操作逻辑；`SelectWork` 改造为读写该父模块 |
| 快捷键 | **Alt + S** | Esc 仍可暂停排除模式（与手动选择作品一致），并新增 Alt + S 作为触发键 |
| 列表生命周期 | **仅当前页面会话** | 排除列表存在内存中，SPA 内（Pixiv 页面切换）有效，整页刷新后丢失。与“手动选择作品”行为一致 |
| 页面可用性 | **同“手动选择作品”** | 在 `pageType.list.Unlisted` 等页面禁用，其余页面可用（镜像 `SelectWork.disablePageList`） |

## 二、关键技术发现（可行性结论）

### 2.1 `store` 会在抓取开始时整体重置 —— 排除列表不能放在 `store`
`Store.ts` 在 `crawlStart` 事件中调用 `reset()`，清空 `idList / resultMeta / result / artworkIDList / novelIDList`（`Store.ts:191-204`）。
- 后果：若把排除列表放进 `store`，用户“先排除、后抓取”时，列表会在抓取开始瞬间被清空，排除失效。
- 结论：**排除列表（以及手动选择的列表）必须放在不随抓取重置的模块里**。这直接否定了原设计里“提取到 `Store.ts`”这一选项，**支持采用“单独的父模块”方案**。父模块（`WorkSelection`）在页面生命周期内一直存在，抓取不会清空它。

### 2.2 `filter.check()` 是过滤的统一关卡
`filter.check()` 在以下路径都会被调用，是应用排除过滤最稳的接入点：
- 各页面 `getIdList` 阶段构建 `store.idList` 时（如 `InitSearchArtworkPage.ts:590`）
- `getIdListFinished` 预检循环（`InitPageBase.ts:366-379`）
- `getWorksData` 获取作品详细数据时（`InitPageBase.ts:348` 等）
- 下载阶段（`Download.ts`、`MergeNovel.ts`）

在 `filter.check()` 内部新增排除检查，可让所有路径自动排除，不会遗漏。

### 2.3 按钮插槽与入口接线
- `Tools.addBtn(slot, text, title, id, emphasis, intent)` 的 `intent` 支持 `'warning' | 'danger'`（`Tools.ts:41` 已确认合法），满足“第一个按钮 warning、第二个 danger”。
- 按钮插槽 `selectWorkBtns` 声明在 `SettingsPanelLayout.ts:79-83` 的 `crawlBtnsBlock` 里。需在同一个 block 增加 `excludeWorkBtns` 插槽。
- `SelectWork` 通过 `InitPageBase.ts:16` 的 `import '../SelectWork'`（副作用导入）触发构造、创建按钮。新模块 `ExcludeWork` 需以相同方式接线。

### 2.4 现有外部依赖（改造时必须同步修改）
- `MergeNovel.ts:24,882,884` 读取 `selectWork.idList` 获取已选小说 id。父模块方案下需改为读取 `workSelection.selectIdList`。
- `states.selectWork`（`States.ts:45`）仅由 `SelectWork` 自身写入，无其他读者；采用父模块方案后将其迁移到 `WorkSelection`，并从 `States.ts` 删除。

## 三、模块拆分与职责

### 3.1 父模块 `src/ts/WorkSelection.ts`（新建，class `WorkSelection`，导出单例 `workSelection`）
作为两个功能**唯一的数据与状态源**，负责互斥与交叉操作：

**数据**
- `selectIdList: IDData[]` —— 手动选择作品的 id 列表（从 `SelectWork` 迁移）
- `excludeIdList: IDData[]` —— 排除作品的 id 列表

**状态**
- `selectActive`、`selectPaused`
- `excludeActive`、`excludePaused`

**方法**
- `enterSelectMode()`：置 `selectActive = true`；**强制关闭排除模式**（`excludeActive = false`、`excludePaused = false`），并触发事件让 `ExcludeWork` 收起指示器/标记态。即“后进入的状态获胜”。
- `enterExcludeMode()`：对称处理，强制关闭选择模式。
- `addSelectId(id, type)`：加入 `selectIdList`；若 `id` 已在 `excludeIdList`，则从中移除，并派发 `EVT.list.excludeWorkRemovedExternally`（让 `ExcludeWork` 移除对应红色标记）。即“后执行的操作获胜”。
- `addExcludeId(id, type)`：对称处理，若 `id` 已在 `selectIdList` 则移除并派发 `EVT.list.selectWorkRemovedExternally`。
- `removeSelectId(id)` / `removeExcludeId(id)`
- `clearSelect()` / `clearExclude()`
- `anyActive` 便捷 getter：是否有任一模式处于 active。

> 注意：父模块只持有**数据/状态/协调逻辑**，不操作 DOM。标记/指示器/按钮等 DOM 行为仍由各功能模块自己负责，通过事件与父模块解耦（避免 `SelectWork` 与 `ExcludeWork` 循环依赖）。

### 3.2 新模块 `src/ts/ExcludeWork.ts`（新建，class `ExcludeWork`，导出 `excludeWork`）
镜像 `SelectWork` 的行为，但针对排除场景：
- 构造函数：`Utils.isPixiv()` 时只创建一次按钮（`created` 守卫，逻辑同 `SelectWork`）。
- 创建红色指示器 `selector`（id 如 `excludeWorkEl`），`updateSelectorEl` 逻辑同 `SelectWork`，颜色改红。
- `addBtn()`：参考 `SelectWork.addBtn`，只添加前两个按钮（见第四节）。
- 点击处理：复用 `SelectWork` 的 `clickThumbnail` / `clickElement` / `addId` 思路，但点击时调用 `workSelection.addExcludeId(id, type)`，并添加红色排除标记 `excludedWorkFlag`；若作品已排除则再次点击取消（从 `excludeIdList` 移除并去掉标记）。
- 监听 `EVT.list.selectWorkRemovedExternally`：收到后移除对应红色标记（交叉操作触发）。
- 互斥：进入排除模式时调用 `workSelection.enterExcludeMode()`。
- 鼠标移动 `moveEvent`、页面切换 `pageSwitch` 后 `reAddAllFlag`（红色标记）、`MutationObserver` 重加标记、中心面板打开时 `tempHide`、Esc 暂停 —— 均参考 `SelectWork`。
- `disablePageList = [pageType.list.Unlisted]`（同 `SelectWork`）。
- `onbeforeunload`：**本期不添加**离开提示（排除不属于“未保存的抓取结果”，刷新仅丢失排除列表，无数据损失风险）。

### 3.3 `src/ts/SelectWork.ts`（改造）
- 删除自身私有的 `_idList` 与 `selectWork` 布尔状态，改为读写 `workSelection.selectIdList` / `workSelection.selectActive` 等。
- `addId` 改为调用 `workSelection.addSelectId(...)`；清除/切换按钮时同步父模块状态。
- `start` setter 改为调用 `workSelection.enterSelectMode()`；退出时 `workSelection` 同步。
- 监听 `EVT.list.excludeWorkRemovedExternally`：收到后移除对应蓝色标记（`selectWork` 自己的 DOM）。
- 删除对 `states.selectWork` 的读写（迁移到 `WorkSelection`）。
- 其余选择器/标记/事件绑定逻辑基本保持不变，仅把“数据读写”改走父模块。

### 3.4 `src/ts/filter/Filter.ts`（新增排除检查）
- 新增私有方法 `checkExcluded(id?: number | string, type?: IDTypeString): boolean`：若 `id` 存在于 `workSelection.excludeIdList` 则返回 `false`，否则 `true`。
- 在 `filter.check()` 开头调用（参数有 `id` 时）：若被排除，`log.warning(...排除原因 + 手动排除...)` 并返回 `false`。
- 这样所有抓取/下载路径自动排除，无需逐个接入。无 `id` 的调用（如 `checkUserId` 只传 `userId`）安全返回 `true`。

### 3.5 `src/ts/store/Store.ts`（新增按 id 移除数据）
新增方法 `removeWorkById(ids: string[])`（用于“抓取完成后用户排除作品”的场景）：
- 从 `idList` 移除（`id` 字符串匹配）。
- 从 `resultMeta` 移除（`idNum` 数值匹配）。
- 从 `result` 移除（`idNum` 数值匹配；多图作品 `_p0`…`_pn` 全部移除）。
- 同时从 `artworkIDList` / `novelIDList` 移除对应 `idNum`，避免后续 `addResult` 因去重而拒绝重新加入。
- 系列小说（`novelSeries`）不进入 `result`，无需处理。
- 移除后派发 `EVT.list.resultDataChanged`（或复用刷新机制，见第八节），供结果面板刷新。

### 3.6 `src/ts/setting/SettingsPanelLayout.ts`（新增插槽）
在 `crawlBtnsBlock` 的 `createSlotBlock([...])` 中增加 `'excludeWorkBtns'`，使排除按钮显示在抓取按钮区、紧邻手动选择按钮。

### 3.7 样式（Less）
- 新增红色指示器样式（参考 `selectWorkEl` 蓝色样式，改红色）。
- 新增 `.excludedWorkFlag`（红色标记，参考 `.selectedWorkFlag` 蓝色样式，改红）。
- 具体类名/位置在实现时对照 `style/` 下 `SelectWork` 相关样式确定。

### 3.8 `src/ts/EVT.ts`（新增事件）
- `selectWorkRemovedExternally`：排除模式加入了已选作品时，通知 `SelectWork` 移除蓝色标记。
- `excludeWorkRemovedExternally`：选择模式加入了已排除作品时，通知 `ExcludeWork` 移除红色标记。
- `resultDataChanged`：抓取后排除作品、store 数据变更后通知结果面板刷新（若现有结果面板已有刷新机制，可复用，不必新增）。

## 四、UI 与按钮

参考 `SelectWork.updateControlBtn` 的三态文字逻辑：

**按钮 1（控制按钮，`warning` intent）**
- 默认文字：`_手动排除作品`，点击进入排除模式。
- 进入后文字变为 `_暂停排除`，点击退出排除模式。
- 退出后文字变为 `_继续排除`，点击重新进入。
- 颜色（intent）固定为 `warning`。

**按钮 2（清空按钮，`danger` intent）**
- 文字：`_清空排除的作品`，默认隐藏。
- 当 `workSelection.excludeIdList.length > 0` 时显示，且文字后附排除数量（参考 `SelectWork.updateCrawlBtn` 的数量显示）。
- 点击清空 `excludeIdList`、移除所有红色标记、隐藏本按钮。

**指示器与标记**
- 排除模式下显示红色 `selector` 跟随鼠标。
- 被排除作品上显示红色 `excludedWorkFlag` 标记；页面切换/重载后通过 `reAddAllFlag` 恢复。

## 五、状态机与互斥规则

```
[空闲]
  │ 点击“手动排除作品” / SelectWork 进入选择
  ▼
[排除模式 active]  ──互斥──  [选择模式 active]
  │  pause=点击“暂停排除”        │  pause=点击“暂停选择”
  ▼                             ▼
[排除模式 paused]          [选择模式 paused]
```
- 进入任一模式会强制退出另一模式（“后进入的状态获胜”），由 `WorkSelection.enterXxxMode()` 保证。
- 同一模式内的 `active / paused` 由各自模块的 setter 维护。

## 六、数据交叉操作规则

| 操作 | 结果 |
| --- | --- |
| 排除模式下点击一个**已被选择**的作品 | 从 `selectIdList` 移除，派发 `selectWorkRemovedExternally` 让 `SelectWork` 去掉蓝色标记；加入 `excludeIdList` 并加红色标记 |
| 选择模式下点击一个**已被排除**的作品 | 从 `excludeIdList` 移除，派发 `excludeWorkRemovedExternally` 让 `ExcludeWork` 去掉红色标记；加入 `selectIdList` 并加蓝色标记 |
| 再次点击已排除/已选的作品 | 从对应列表移除并去掉标记（toggle 取消） |

## 七、抓取过滤集成（排除发生在抓取前）

`filter.check()` 内的 `checkExcluded` 在 `getIdList`、预检、`getWorksData`、下载阶段都会拦截，因此被排除的作品不会进入 `store.idList`，也不会被抓取/下载。此路径**不需要**调用 `Store.removeWorkById`。

---

## 八、抓取后排除（移除已抓取的数据）

若用户在抓取完成后（`crawlComplete` 之后、`crawlStart` 之前）排除作品：
1. `ExcludeWork` 调用 `workSelection.addExcludeId(id, type)`。
2. 若 `store` 中已有该作品数据，调用 `store.removeWorkById([id])` 移除 `idList / resultMeta / result` 及去重表项。
3. 派发刷新事件，结果面板更新（需实现时确认结果面板现有的刷新钩子，若无则新增 `resultDataChanged` 监听）。

> 因为 `store` 在下次 `crawlStart` 会 reset，此移除只在“本次抓取结果还保留在内存中”的窗口期有效，符合“会话级”生命周期预期。

## 十、风险与注意事项

- **父模块改造回归风险**：`SelectWork` 是成熟模块，迁移其数据与状态到 `WorkSelection` 需逐处核对，建议先完整跑通 `SelectWork` 原有行为再做排除功能。
- **DOM 与数据解耦**：标记是 DOM 元素、由各自模块管理；交叉操作通过 `EVT` 事件通知对方移除标记，父模块不直接碰 DOM，避免循环依赖。
- **store 重置时序**：排除列表绝不放 `store`；只有“抓取后排除”才调用 `store.removeWorkById`，且依赖 `store` 尚未被下次 `crawlStart` reset。
- **系列小说**：`novelSeries` 不进入 `result`，排除系列仅在“未来抓取”时通过 `filter.check` 拦截生效，不影响已抓取数据。
- **i18n**：新增文案须遵守 `notes/翻译多语言文本的 prompt.md`；多条翻译集中改完后统一编译一次。
