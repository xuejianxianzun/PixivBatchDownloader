# 为多图作品下方的缩略图列表添加选择按钮

## 概述

`src/ts/pageFunciton/DisplayThumbnailListOnMultiImageWorkPage.ts` 模块会在多图作品页面里添加缩略图列表，显示里面的每一张图片。
该模块的样式文件是 `src/style/DisplayThumbnailListOnMultiImageWorkPage.less`。

有些用户希望可以在这个缩略图列表上进行选择，标记自己想要下载的图片，然后开始下载（即只下载多图作品里的部分图片）。所以我想在列表容器顶部添加一个操作栏。

操作栏里的内容布局为两端排列，左侧是选择和帮助按钮：
- 手动选择
- 全选
- 清空
- 帮助

右侧只有一个按钮：
- 下载

所有需要显示在页面上的文字都要进行 i18n 处理。

## 数据

1. 添加一个状态标记，保存当前是否处于选择图片的状态。
2. 新增一个变量 `idData`，类型为 `IDData | undefined` 类型，每次执行 `init` 时重置为 `undefined`。如果用户手动选择了部分图片，则在里面添加 `IDData` 里所有的属性，并在 `downloadIndexes` 属性里保存被选择的图片的 index。

每次执行 `init` 时重置上面两个数据，并退出选择模式。

## 按钮的作用

需要先添加一个“为图片添加选择标记”的方法，根据 `idData.downloadIndexes` 为列表里的所有图片添加选择标记，为没有选择的图片移除标记（如果有）。

### 全选

填充 `idData` 数据，并在 `downloadIndexes` 里添加所有 index。然后更新图片的选择标记。

### 手动选择

点击它会切换进入/退出选择状态。

当进入选择状态时，在鼠标光标处显示特殊标记；之后点击任意图片时，阻止这次点击事件传播，然后处理选择逻辑：如果该图片未选中，则选择该图片；如果该图片已选择，就取消选择它。然后更新 `idData.downloadIndexes` 里的数据，并更新选择标记。

### 清空

把 `idData` 重置为 `undefined`，然后移除所有选择标记。

不会退出选择状态。

### 帮助

点击它会使用 `MsgBox` 模块显示帮助信息：
`如果你只想下载这个作品里的部分图片，可以先选择你需要的图片，然后下载。<br>进入手动选择模式之后，点击一张图片可以切换它的选中/未选中状态。`。

### 下载

执行 `EVT.fire('crawlIdList', [idData])`，然后退出选择状态。

备注：
- 当 `idData.downloadIndexes` 属性存在且不为空数组时，使用 `idData`。
- 如果 `idData` 为 `undefined`，或者 `idData.downloadIndexes` 是空数组，则构造一个临时的 `idData` 数据来使用。这个临时数据里没有 `downloadIndexes` 属性，以便下载所有图片。

## UI

为按钮添加 `.blueTextBtn` 类名来显示为蓝底白字的按钮，但有些例外：
- “清空”按钮的背景颜色覆写为 `#bb7878` 以显示危险操作的警告色。
- “帮助”按钮不添加 `.blueTextBtn` 类名，是简单的纯文字按钮。在亮色主题里，它的默认颜色是 `#888`，hover 时颜色为 `#666`；在暗色主题里，默认颜色为 `#999`，hover 颜色为 `#d6d6d6`。

需要使用到两个标记元素：
1. 进入选择状态之后，在鼠标光标处显示一个特殊的选择标记，并跟随光标
2. 需要在被选择的图片上添加“已选择”的标记

这两个标记的样式可以参考 `src/ts/SelectWork.ts` 里的 `selector` 和已选择的标记，使用不同的 className。并且把选择状态的标记的背景颜色从蓝色改为黄色 `#ffff00`。

## 可行性分析

总体结论：**可行**。核心下载路径（`crawlIdList` + `downloadIndexes`）是成熟模式，已被多个模块验证；UI 与标记元素可复用 `SelectWork` / `CrawlRecommendWorks` 的既有写法。但有 1 个关键坑、2 个实现细节、以及若干需澄清的点，见下文。

### 1. 核心下载逻辑（可行，已有先例，但有坑）

- `downloadIndexes` 已在 `IDData`（store/StoreType.d.ts:40）中定义，全链路支持：`EVT.fire('crawlIdList', [idData])` → `InitPageBase.crawlIdList`（crawl/InitPageBase.ts:270）→ `saveArtworkData.save(data, downloadIndexes)`（同文件 462/549）→ `store.addResult(data, requestedIndexList)`（store/Store.ts:113）。
- 这条「只下载部分图片」的路径早已被 `ShowOriginSizeImage`、`ImageViewer`、`ButtonsOnArtworkThumbOnPC`、`PreviewWork` 等模块使用，本功能直接复用即可。
- ⚠️ **关键坑**：`Store.addResult` 中 `if (requestedIndexList) { indexList = requestedIndexList } else { ...全部... }`。即 **`downloadIndexes: []`（空数组）会被当作「下载 0 张」而不是「下载全部」**。文档「备注」里「为空数组时构造没有 downloadIndexes 的临时 idData」的做法是对的、**且必须严格这么做**——实现时绝不能把空数组传给 `crawlIdList`，否则会下载到 0 张图。

### 2. 数据层（可行，但 type 不能取自 li 的 data-worktype）

- `id`：`li` 已被 `WorkThumbnail` 在运行时装饰，`dataset.workid` 即作品 id（可靠，无需用 `Tools.getIllustId()` 逐个取，见第 6 节）。
- `downloadIndexes`：`number[]`，从 0 开始，与 `li` 的 `data-index` 对齐。
- ⚠️ **`type` 不能取 `li.dataset.worktype`**：`WorkThumbnail.bindEvents`（WorkThumbnail.ts:112-115）只会把 `data-worktype` 写成 `'illusts'` 或 `'novels'`（其类型签名是 `'illusts' | 'novels'`，见第 85 行），**漫画/动图作品的缩略图上也会被写成 `'illusts'`**。若把它当作 `IDData.type` 传给 `crawlIdList`，manga/ugoira 会被错误当成 illusts，可能导致下载异常。因此 `type` 必须用 `createThumbList` 里已取到的 `workData.body.illustType`（0/1/2）映射成 `illusts`/`manga`/`ugoira`（决策点 4 已确认），不要写死、也不要从 `data-worktype` 取。

### 3. 操作栏与按钮（可行，沿用既有约定）

- 按钮样式沿用 `CrawlRecommendWorks.ts` 的写法：`<button class="blueTextBtn hasRippleAnimation"><span data-xztext="_key"></span><span class="ripple"></span></button>`，再用 `lang.register(span)` 应用 i18n、`wiki.registerBtn(btn)` 注册 Wiki 长按链接。
- 操作栏布局（左：全选/手动选择/清空/帮助；右：下载）作为 `#viewerWarpper` 的第一个子元素插入（`display()` 里 wrapper 插入后追加），或放在 `ul` 之前。
- 清空按钮背景色覆写为 `#bb7878`；帮助按钮不加 `.blueTextBtn` 且按主题变色。这些纯 CSS 即可，写在 `DisplayThumbnailListOnMultiImageWorkPage.less` 里，用 `.theme-white` / `.theme-dark` 作用域（wrapper 已 `theme.register`）。

### 4. 手动选择模式与点击事件（可行，但拦截方式要注意）

- 现状：`display()` 给每个 `li img` 绑定了 `click` 打开 ImageViewer（autoStart）。新功能进入选择模式后，点击图片要改为「切换选中」且不打开查看器。
- ⚠️ 注意：ImageViewer 的点击处理是**直接绑在 `img` 元素上的同 target 冒泡监听器**。文档说「阻止点击事件传播」——`ev.stopPropagation()` 只能阻止冒泡到祖先，**不能**阻止同一元素上的其它监听器。因此必须用**捕获阶段**监听：在 `#viewerWarpper`（或 `ul`）上 `addEventListener('click', handler, true)`，handler 内 `if (this.selecting) { ev.stopPropagation(); ev.preventDefault(); toggle(index) }`。捕获阶段先于 target 的冒泡监听器执行，stopPropagation 会阻止事件继续下传到 `img` 的监听器，从而拦截 ImageViewer 打开。
- 该捕获监听要在每次 `display()` 重建 wrapper 时重新绑定（或绑在稳定的父容器上）。

### 5. 标记元素（可行，且已与「手动选择作品」隔离）

- 选择状态的「光标跟随标记」：仿 `SelectWork.createSelectorEl()`，自建独立元素（如 id `thumbnailListSelectorEl`）append 到 body，进入模式后跟随鼠标，背景色按文档改为 `#ffff00`。与 `SelectWork` 的 `#selectWorkEl` 不冲突（不同 id/class）。
- 被选中图片的「已选择」标记：仿 `SelectWork.addSelectedFlag`，往 `li[data-index="x"]` 插入一个 `<i>`（**使用与 `selectedWorkFlag` 不同的 class**），并给 `li` 补 `position: relative`（若无定位）。
- ⚠️ 关于 `ppd-workThumbnail`：这些图片 `li` 在运行时**已经被 `WorkThumbnail` 装饰过**（见第 6 节），带 `ppd-workThumbnail` 类是既成事实，不由本功能添加、也不应移除。但「手动选择作品」功能（`SelectWork`）早已对它们做了隔离：`SelectWork.selectAll()`、`clickThumbnail()`、`addSelectedFlag()` 都通过 `displayThumbnailListOnMultiImageWorkPage.checkLI(el)`（即判断是否存在 `xz-thumb-li` 类）跳过多图缩略图。因此：
  - 我们的图片选择标记要用**不同 class**，并且即便用 `.ppd-workThumbnail` 选择器，`SelectWork.addSelectedFlag` 也会因 `checkLI` 跳过、不会误改这些 `li`。
  - 不必担心「加 ppd-workThumbnail 类导致冲突」——这个类本来就存在，`SelectWork` 已经能正确忽略它们。原先「不要给这些 li 加 ppd-workThumbnail 类」的说法是错的（基于误判示例过时），现已更正。

### 6. 文档 HTML 示例是准确的

上一轮分析误判示例「过时、与现状不符」，这是错的。这些 `li` 的属性来自**两个模块叠加**，运行时确实存在：

- `DisplayThumbnailListOnMultiImageWorkPage.createThumbList`（DisplayThumbnailListOnMultiImageWorkPage.ts:128）生成 `li`：`class="xz-thumb-li"`（即 `Config.ImageViewerLI`）+ `data-index` + 内部 `<a href="/artworks/...">`。
- `WorkThumbnail.bindEvents`（WorkThumbnail.ts:107-116）会对含有作品链接的缩略图做运行时装饰：补 `data-mouseover="1"`、`data-workid`、`data-worktype`、`ppd-workThumbnail` 类。**多图缩略图里的 `<a href="/artworks/...">` 正符合 `WorkThumbnail` 的查找条件，因此这些 `li` 也会被装饰**——这正是示例里 `ppd-workThumbnail`/`data-workid`/`data-worktype`/`data-mouseover` 的来源。

结论：示例里的 `ppd-workThumbnail`、`data-workid`、`data-worktype`、`data-index`、`xz-thumb-li` 都是真实可用的。实现时可直接用 `li.dataset.workid` 取作品 id、用 `data-index` 取图片 index；`ppd-workThumbnail` 类已存在，无需本功能添加，也不应移除。

### 7. 生命周期 / 重置（可行）

- `init()` 在 pageSwitch 时调用并先 `remove()`，已有「每次进入页面重置」的骨架。把 `idData = undefined`、`selecting = false`、移除标记、移除光标标记的逻辑放进 `init()`（或 `remove()`）即符合文档要求。
- 注意 `display()` 是 `setTimeout(0)` + 轮询等待 target 的异步流程，操作栏与捕获监听要在 wrapper 插入后再挂。

### 8. 与「全选当前显示的作品」按钮（上一任务）的关系（已隔离，不冲突）

- 上一任务的 `SelectWork.selectAll` 查询 `.ppd-workThumbnail` 后，会用 `displayThumbnailListOnMultiImageWorkPage.checkLI(el)`（判断 `xz-thumb-li`）**跳过**多图缩略图（SelectWork.ts:369-371）；`clickThumbnail`（413-415）、`addSelectedFlag`（572-574）同样跳过。因此即使图片 `li` 带有 `ppd-workThumbnail`，也**不会被当成作品选入**。二者数据层也独立（SelectWork 走 `WorkSelection` + 整作品 `crawlIdList`；本功能走自己的 `idData` + 带 `downloadIndexes` 的 `crawlIdList`，只下部分图片）。
- 唯一需注意：本功能要新增一个**捕获阶段**的 click 监听（见第 4 节）来拦截 ImageViewer。它与 `SelectWork` 在 `document.body` 上的捕获监听（SelectWork.ts:109-115）共存时，靠各自的模式守卫区分（`this.selecting` / `canSelect()`），互不影响。本功能的选择是「图片级」，不进入 `WorkSelection`。

### 需要确认的点

1. **i18n key 命名**：本功能的「全选 / 手动选择 / 清空 / 帮助 / 下载」是否用图片级专用 key（如新增 `_全选图片`、`_手动选择图片`、`_清空已选择的图片`，帮助文案新 key），还是复用现有通用 key（`_帮助` 8138、`_下载` 2744）？注意现有 `_全选当前显示的作品`(4136)、`_手动选择作品`(4088)、`_清空选择的作品`(4128) 语义是「作品级」，直接复用到图片级会混淆。
2. **未选任何图时点「下载」的行为**：文档说构造临时 idData（无 `downloadIndexes`）下载全部——符合预期；但是否要在「0 张被选中」时点下载给个确认/提示，避免用户误以为会只下选中的图？
3. **Wiki 注册**：是否要把新按钮（全选/手动选择/清空/下载）加入 `setting/Wiki.ts` 的 `buttonsSchema`（类似上一任务注册 `selectAllWorks`），以支持长按打开 Wiki 说明？
4. **type 取值**：确认用 `workData.body.illustType` 映射 `illusts`/`manga`/`ugoira`（推荐），而非写死 `illusts`。

### 已确认的决策（来自与用户的确认）

1. **i18n key 命名**：使用**图片级专用 key**，不复用作品级 key。新增 `_全选图片`、`_手动选择图片`、`_清空已选择的图片`、以及帮助文案 key（如 `_为多图作品里的图片选择_帮助` 或类似）；`_帮助`、`_下载` 可酌情复用现有通用 key（`_帮助` 8138、`_下载` 2744）。所有新增 key 须补全 6 种语言。
2. **空选下载行为**：未选任何图时点「下载」= 构造无 `downloadIndexes` 的临时 `idData`，下载该作品**全部**图片（按文档备注）。不弹确认、不禁用按钮。
3. **Wiki 注册**：**暂不**把新按钮注册进 `setting/Wiki.ts` 的 `buttonsSchema`（后续如需再补）。
4. **type 取值**：用 `workData.body.illustType`（0/1/2）映射 `illusts`/`manga`/`ugoira`，不写死 `illusts`。**注意不能图省事用 `li.dataset.worktype`**——它被 `WorkThumbnail` 统一写成 `'illusts'`（漫画/动图也如此），用在 `IDData.type` 上会导致类型错误（见第 2 节）。
