# 如何添加一个设置项的表单元素

本文件只说明如何在 `src\ts\setting\OptionsHtml.html` 中编写设置项的 HTML。添加设置项的完整流程、设置类型、默认值、双向绑定、i18n 和 `OptionConfigs.ts` 配置，见 [添加设置项-add setting item.md](./添加设置项-add%20setting%20item.md)。

`OptionsHtml.html` 会被包装进 `.settingForm`，再由设置面板重新排版。每个 `<div class="option">` 是一个独立设置项；`data-no` 会将它关联到 `OptionConfigs.ts` 中同编号的配置。

## 1. 编写前的判断

1. 先在 `OptionsHtml.html` 搜索最接近的新旧设置项，优先复制其结构再修改，不要从零拼凑 className。
2. 确认每个需要持久化的表单控件都有唯一的 `name`，且它和 `Settings.ts`、`FormType.d.ts`、`FormSettings.ts` 中的名称一致。
3. 判断控件是否属于 `FormSettings.ts` 的标准绑定类型：`checkbox`、`radio`、文本 `input`、`datetime-local` 输入框、`textarea`。只有把名称加入相应的 `inputFileds` 数组，标准控件才会自动从 `settings` 恢复值，并在用户修改时调用 `setSetting`。
4. `select`、文件选择器、动态列表、按钮、插槽，以及有特殊校验或派生状态的控件，不会自动绑定。必须复用或新增专用模块来读取设置、更新视图和保存值；不要只添加 HTML。

## 2. 外层设置项和标题

每个独立设置项使用下面的外层结构：

```html
<div class="option" data-no="106">
  <a href="" target="_blank" class="settingNameStyle">
    <span data-xztext="_设置名称"></span>
  </a>

  <!-- 此设置项的控件 -->
</div>
```

- `data-no` 必须是未使用的编号，并与 `OptionConfigs.ts` 的 `no` 完全一致。
- `class="option"` 和 `data-no` 是必需的。设置面板、置顶、搜索、隐藏和分类布局都依赖它们。
- 名称通常使用 `<a href="" target="_blank" class="settingNameStyle">`。`Wiki.ts` 会处理设置名称的链接；即使暂时没有 Wiki 页面，也沿用这个结构。
- 名称文字应放进单独的 `<span data-xztext="_设置名称"></span>`。不要把混有开关、图标或其他 HTML 的外层元素整体设置 `data-xztext`，否则翻译更新会破坏子元素。
- 如果标题本身没有其他子元素，也可以直接在 `<a>` 上使用 `data-xztext`。名称内需要额外的问号、图标或颜色文字时，使用单独的 `<span>` 更安全。
- 不需要子选项的设置，把控件直接放在 `.option` 内即可。`.option` 已是可换行的 flex 容器。

## 3. 显示文本、翻译和悬浮提示

### 3.1 普通可翻译文字

使用 `data-xztext`，可用于 `span`、`label`、`button`、`a` 等实际显示文字的元素：

```html
<span data-xztext="_最小值"></span>
<label for="example" data-xztext="_启用"></label>
<button type="button" class="textButton" data-xztext="_添加"></button>
```

- 每个会显示给用户的自然语言文本都应使用 i18n key；固定的技术文字（如 `EPUB`、`1200px`、比较符号）可以直接写入。
- 可翻译的 placeholder 使用 `data-xzplaceholder="_提示文字"`；不需要翻译的示例值可直接使用 `placeholder="tag1,tag2"`。
- `data-title`、`data-msg`、`data-xztip` 的值也都是 `langText.ts` 中的 i18n key。

### 3.2 小型悬浮提示：`has_tip`

当一小段补充说明适合鼠标悬停查看时，在实际触发元素上同时添加 `has_tip` 和 `data-xztip`：

```html
<a
  href=""
  target="_blank"
  class="has_tip settingNameStyle"
  data-xztip="_设置名称的提示"
>
  <span data-xztext="_设置名称"></span>
  <span class="gray"> ? </span>
</a>
```

也可以把它用于 `label` 或输入框：

```html
<label
  for="example"
  class="has_tip"
  data-xztext="_选项名称"
  data-xztip="_选项名称的提示"
></label>
```

- `has_tip` 只负责标记提示触发元素；`data-xztip` 是 i18n 系统使用的属性，运行时会转换为提示模块读取的内容。不要手写 `data-tip`。
- 标题提示通常额外显示 `<span class="gray"> ? </span>`，让用户知道可以悬停查看说明。
- 提示应简短。如果需要多段说明、示例或操作说明，使用下面的帮助按钮。

### 3.3 弹窗帮助按钮：`showMsgBtn`

点击后由 `FormHelpManager` 使用 `MsgBox` 显示完整帮助：

```html
<button
  type="button"
  class="gray textButton showMsgBtn"
  data-title="_设置名称"
  data-msg="_设置名称的帮助"
  data-xztext="_帮助"
></button>
```

- `showMsgBtn`、`data-title`、`data-msg` 都是必需的。
- `data-title` 和 `data-msg` 都填写 i18n key；按钮文字通常使用 `_帮助`。
- 此按钮只显示说明，不保存设置值。

### 3.4 面板内展开/收起的帮助：`toggleArea`

短帮助也可以直接展开在设置面板内：

```html
<button
  type="button"
  class="gray textButton toggleArea"
  data-toggle-Target="#exampleTip"
  data-xztext="_提示"
></button>
<p class="tip" id="exampleTip">
  <span data-xztext="_设置名称的帮助"></span>
</p>
```

- `data-toggle-Target` 必须是目标元素的唯一 CSS 选择器，通常使用唯一 `id`。
- 目标提示区通常使用 `<p class="tip">`；命名规则等带复制行为的帮助区还会使用 `namingTipArea`。
- 使用弹窗还是展开区：完整独立说明用 `showMsgBtn`；需要和当前控件一起对照的内容用 `toggleArea`。

## 4. 标准表单控件

### 4.1 总开关：`checkbox_switch`

用于启用或禁用整个设置项，或启用子选项：

```html
<input
  type="checkbox"
  name="exampleSwitch"
  class="need_beautify checkbox_switch"
/>
<span class="beautify_switch" tabindex="0"></span>
```

- `input` 后必须紧接一个 `<span class="beautify_switch" tabindex="0"></span>`。`FormBeautify` 依赖相邻元素绑定鼠标和键盘操作，并由 CSS 绘制开关。
- `need_beautify checkbox_switch` 是固定组合；不要省略任一 class。
- 如果需要标签，给 input 添加唯一 `id`，再使用 `<label for="...">`。若标签放在开关前面，仍要保持 input 与美化 span 相邻。
- HTML 中的 `checked` 只影响设置尚未恢复前的瞬时状态；真正默认值由 `Settings.ts` 的 `defaultSettings` 决定。不要仅修改 `checked` 来改变默认设置。

### 4.2 普通复选框：`checkbox_common`

用于多个可独立勾选的条件：

```html
<input
  type="checkbox"
  name="exampleType"
  id="exampleType"
  class="need_beautify checkbox_common"
/>
<span class="beautify_checkbox" tabindex="0"></span>
<label for="exampleType" data-xztext="_选项名称"></label>
```

- 顺序必须是 `input`、美化 `span`、`label`。
- `id` 必须唯一，`label for` 必须与其一致；这提供可点击文字和美化状态的高亮。
- 每个独立 checkbox 应使用不同的 `name`，对应不同的 boolean 设置。

### 4.3 单选按钮：`radio`

同一组单选项共用一个 `name`，每个选项具有不同的 `value`：

```html
<input
  type="radio"
  name="exampleMode"
  id="exampleModeA"
  class="need_beautify radio"
  value="a"
  checked
/>
<span class="beautify_radio" tabindex="0"></span>
<label for="exampleModeA" data-xztext="_模式A"></label>

<input
  type="radio"
  name="exampleMode"
  id="exampleModeB"
  class="need_beautify radio"
  value="b"
/>
<span class="beautify_radio" tabindex="0"></span>
<label for="exampleModeB" data-xztext="_模式B"></label>
```

- 项目中单选按钮的固定 class 是 `need_beautify radio`，不是 `radio_common`。
- 每个 radio 后必须紧接 `.beautify_radio`，并使用唯一 `id` 和匹配的 `label for`。
- 同组 radio 的 `name` 对应一个 string 设置，`value` 是保存的实际值。`checked` 同样只作为恢复前的初始 HTML 状态。

### 4.4 文本输入框和日期时间输入框

普通短文本、数字和日期时间控件通常如下：

```html
<label for="exampleValue" data-xztext="_数值"></label>
<input
  type="text"
  name="exampleValue"
  id="exampleValue"
  class="setinput_style blue"
  value="0"
/>
```

```html
<input
  type="datetime-local"
  name="exampleDate"
  class="setinput_style blue postDate"
/>
```

- 普通短输入框使用 `setinput_style blue`；`setinput_style` 提供尺寸、边框和主题样式，`blue` 保持现有强调色。
- 需要特殊宽度时优先复用已有 class，例如日期时间使用 `postDate`、收藏数使用 `bmkNum`；`src\style\style.less` 里已经有一些预设的宽度类名，如 `.w50`、`.w100`。如果没有合适的预设宽度，可以自行添加一个类名。不要为了设置某一个元素的宽度在通用样式里硬编码 `data-no`。
- `FormSettings` 会在 `change` 时保存文本值。数值范围、格式和类型转换应由 `Settings.setSetting()` 或专用模块处理，不能只依靠 HTML 的 `value`。

### 4.5 多行输入框

```html
<textarea
  class="centerPanelTextArea beautify_scrollbar"
  name="exampleList"
  rows="1"
  placeholder="tag1,tag2"
></textarea>
```

- 使用 `centerPanelTextArea beautify_scrollbar`。前者使输入框占据合适宽度并支持自适应高度，后者保持滚动条样式。
- `rows="1"` 是常用初始高度；`FormSettings` 和 `Tools.setRows()` 会在内容变化后调整高度。
- textarea 通常放入 `subOptionWrap flexBasis100`，让它占满一行；否则可用宽度通常不足。

### 4.6 原生 select

```html
<select name="exampleSelect" class="beautify_scrollbar">
  <option value="a">A</option>
  <option value="b">B</option>
</select>
```

- select 具有面板内置样式，`beautify_scrollbar` 用于下拉列表滚动条。
- 当前 `FormSettings` 不自动处理 select。只有在已有专用逻辑（如命名标记插入）时才使用；新增的持久化 select 必须自行绑定 `change`、恢复设置值，并补充类型声明。

## 5. 子选项区域：`subOptionWrap` 和 `optionLine`

### 5.1 由总开关控制显示

```html
<input
  type="checkbox"
  name="exampleSwitch"
  class="need_beautify checkbox_switch"
/>
<span class="beautify_switch" tabindex="0"></span>

<div class="subOptionWrap flexBasis100" data-show="exampleSwitch">
  <!-- 子选项 -->
</div>
```

- `data-show` 的值必须与控制开关的 `name` 完全一致。
- 控制控件必须是 `checkbox_switch`；`FormBeautify` 会查找 `.subOptionWrap[data-show="控件名称"]` 并按选中状态显示或隐藏它。
- 一个开关只应对应一个 `data-show` 容器。当前实现只查找第一个匹配容器；若需要多个区域，应使用一个外层 `subOptionWrap`，再在内部用 `optionLine` 分行。
- `subOptionWrap` 应放在控制开关之后。它可以包含任意标准控件，内部控件仍需要按正常步骤绑定设置。

### 5.2 宽度与布局

- 默认 `.subOptionWrap` 会占据标题右侧的剩余空间，适合少量横向控件。
- 添加 `flexBasis100`，让它从新行开始并占满整行。包含 textarea、动态列表、较多控件或多行内容时通常需要它。
- 添加 `noGrow`，让区域不再自动占据右侧剩余空间，适合很短的数字输入等紧凑内容。
- `optionLine` 是 `subOptionWrap` 内独占一整行的 flex 容器。复杂子选项应按逻辑分成多个 `optionLine`，每行放一组相关控件：

```html
<div class="subOptionWrap flexBasis100" data-show="exampleSwitch">
  <div class="optionLine">
    <span data-xztext="_最小值"></span>
    <input type="text" name="exampleMin" class="setinput_style blue" />
  </div>
  <div class="optionLine">
    <span data-xztext="_最大值"></span>
    <input type="text" name="exampleMax" class="setinput_style blue" />
  </div>
</div>
```

- `verticalSplit` 可在同一行添加视觉分隔；`gray` 用于弱化辅助文字；`mr4` 等间距 class 只在确有布局需求时复用。优先使用 flex 布局和 `optionLine`，不要用大量 `&nbsp;` 解决排版。

## 6. 其他常用组件

### 6.1 触发自定义事件的按钮

设置面板入口会为 `.fireEvent` 按钮绑定 `data-event` 指定的 EVT 事件：

```html
<button
  type="button"
  class="textButton gray fireEvent"
  data-event="exportSettings"
  data-xztext="_导出设置"
></button>
```

只有当 `EVT.ts` 中存在该事件，且对应模块已经监听它时才能使用。按钮本身不自动保存设置。

### 6.2 slot 和动态内容

`<slot data-name="..."></slot>` 由专用模块填充，例如保存命名规则、动态列表或特殊管理器。它们不属于 `FormSettings` 的自动绑定范围；新增 slot 时必须同时实现创建、渲染、更新和事件处理模块。

## 7. 最小模板

### 没有子选项的开关

```html
<div class="option" data-no="106">
  <a href="" target="_blank" class="settingNameStyle">
    <span data-xztext="_设置名称"></span>
  </a>
  <input
    type="checkbox"
    name="exampleEnabled"
    class="need_beautify checkbox_switch"
  />
  <span class="beautify_switch" tabindex="0"></span>
</div>
```

### 带提示、总开关和子选项

```html
<div class="option" data-no="106">
  <a
    href=""
    target="_blank"
    class="has_tip settingNameStyle"
    data-xztip="_设置名称的提示"
  >
    <span data-xztext="_设置名称"></span>
    <span class="gray"> ? </span>
  </a>
  <input
    type="checkbox"
    name="exampleEnabled"
    class="need_beautify checkbox_switch"
  />
  <span class="beautify_switch" tabindex="0"></span>
  <div class="subOptionWrap flexBasis100" data-show="exampleEnabled">
    <div class="optionLine">
      <label for="exampleValue" data-xztext="_数值"></label>
      <input
        type="text"
        name="exampleValue"
        id="exampleValue"
        class="setinput_style blue"
      />
    </div>
  </div>
</div>
```

## 8. 完成前检查

1. `data-no` 未重复，且 `OptionConfigs.ts` 中存在相同 `no` 的配置，位置符合用户要求。
2. 所有持久化控件的 `name`、`XzSetting` 类型、默认值、`FormType.d.ts`、`FormSettings.ts` 分类已完整接线。
3. 每个 checkbox / radio 后都有正确、紧邻的美化 `span`；需要 label 的控件具有唯一 `id` 和匹配的 `for`。
4. `data-show` 的值与总开关的 `name` 一致，并且一个总开关只会创建一个平级 `subOptionWrap`。
5. 所有可见自然语言、placeholder、悬浮提示、帮助标题和帮助正文都已添加或复用 i18n 文本。
6. 需要特殊保存、动态渲染、外部存储或派生视图时，已实现专用模块，并在设置改变时更新视图。
7. 未为当前任务修改无关设置项、全局样式或生成的 `dist/` 文件。
