# 把更新说明文本转换为 HTML 格式

每次发布更新之前，我会先整理出 markdown 格式的更新说明文本，然后转换成 html 格式，以便在浏览器里显示。

## 转换规则

读取 `notes/把 Markdown 文本转换为 HTML 格式.md` 并使用里面的转换规则。

## 处理转换结果

下载器的 i18n 系统里有 6 种语言的文本（按顺序依次是：简体中文、繁体中文、英语、日语、韩语、俄语）。
转换结果是简体中文文本，把它翻译成其他 5 种语言，完成后把结果填充到 `src\ts\langText.ts` 的 `_版本更新说明` 属性的数组里。如果这个数组里之前已经有内容了，就用这次翻译的结果覆盖之前的内容。

## 执行经验与踩坑记录（供后续重复执行时参考）

以下经验来自 2026-09 的一次实际执行（把 85 行 md 更新说明转换为 6 语言 HTML 并写入 `_版本更新说明`）。每次发版都要走一遍这个流程，按此清单执行可以显著提速、减少返工。

### 1. 推荐执行流水线

```
提取 md 原文 → node 脚本程序化转换（勿手工抄录）→ 查证既有术语译法
→ 生成 6 语言内容 → 脚本整体替换占位符 → prettier + npm run ts
→ 结构校验脚本 → 删除临时文件 → git status 复查
```

`_版本更新说明` 通常已经有内容，此时任务 = 整体替换这个数组。

### 2. 脚本化处理的技巧

- **不要手工把 md 抄进代码**：写一个 node 脚本直接从本文档提取 ```md 代码块（`/```md\n([\s\S]*?)```/`）再按规则转换，避免抄录偏差。
- **bash 内联 `node -e` 极易被引号搞挂**（嵌套单双引号 + 反引号）：凡是逻辑稍长的检查，一律写成 `_tmp_xxx.js` 临时脚本再 `node` 执行，用完删除。
- **langText.ts 的 key 名含中文**（如 `_版本更新说明`），正则 `[A-Za-z0-9_]` 匹配不到：用文本切分更稳，例如 `s.split('  _版本更新说明: [\n')[1].split('\n  ],')[0]`。
- 处理前可用 `fs.readFileSync(...).includes('\r\n')` 确认行尾，避免 CRLF 影响字符串匹配。

### 3. 转换与引号

- 规则同 `把 Markdown 文本转换为 HTML 格式.md`：一次全局 `\n\n`→`\n`、行尾加 `<br>`（仅最后一行不加）、`### ` 标题→`<strong>`、反引号→`<span class="blue">`、md 链接→`<a ... target="_blank">`。
- **引号风格按语言区分**：简中弯引号“ ”（md 源文里若出现 ASCII 直引号 `"` 需顺手修正）；繁中/日文「」；俄文« »；英/韩保持直引号。

### 4. 翻译一致性

- 翻译前先在 langText.ts 里 grep 既有译法（开始抓取、手动选择/排除作品、用户屏蔽名单、约稿、移动端等），**沿用官方术语，不要新造**。
- 6 语言按顺序：简/繁/英/日/韩/俄；每语言一个多行模板字符串，行数、`<strong>`、`<span class="blue">` 位置与 emoji 必须逐行对应简中，HTML 标签原样保留。

### 5. 发布前结构校验（重要，别跳过）

写完不要只靠编译通过就收工，写个校验脚本**从落盘文件重新解析**该数组，逐语言核对：

- 共 6 条；每语言行数一致（与转换后行数相同）
- `<strong>` 开闭配对（如 17 对）、`<span class="blue">` 开闭配对（如 7 处）数量六语言一致
- 快捷键高亮序列一致（`Alt`+`W`、`V`、`V`、`B`、`Alt`+`Z` 等出现位置对齐）
- 行尾 `<br>` 数量 = 总行数 − 1（末行无）
- 六语言同号行同为标题/同为正文，0 错位
- 简中无 ASCII 直引号残留
- **警惕：不同语言字符数恰好相同可能是巧合**（曾出现繁/简同为 2215 字符），不能凭长度判断译文正确，要逐行对比内容
- 校验脚本里的“预期常量”先由真实数据统计得出再写死，别先拍脑袋（曾把 17/7 误写成 13/12）

### 6. 收尾

- `npx prettier -c --write src/ts/langText.ts` + `npm run ts` 编译
- 删除全部 `_tmp_*` 临时文件；`git status` 确认无游离改动
- 注意区分用户自己的发布准备改动（CHANGELOG.md、package.json、manifest.json 的版本号等），不要误碰
