# 允许用户设置快捷键

## 概述

现在下载器有很多快捷键，但都是内置的。有些用户想修改快捷键（特别是当一些快捷键与其他扩展有冲突时），所以需要添加自定义快捷键的功能。

下载器的快捷键分为一级快捷键和二级快捷键。一级快捷键是在 pixiv 的网页里始终生效的，可以直接使用（不过有些只在特定页面里生效）；二级快捷键则是某些功能的子快捷键。例如：
- Alt + X 是一级快捷键，它用来切换显示下载器的设置面板，在任何时候都可以使用（只要在 pixiv 的页面里）
- 在预览作品时，可以使用二级快捷键（例如复制作品信息的 `Alt + C`）。二级快捷键仅在对应功能界面显示时工作；如果该界面未显示，它就不会生效。

## 需求

- 浏览器扩展有让用户自定义快捷键的功能，可以使用这个机制。我不知道 Chrome 和 Firefox 浏览器在这方面有没有差异，希望能兼容两种浏览器。
- 只需要让用户设置一级快捷键，不需要让用户设置二级快捷键。
- 如果用户修改了这些快捷键，那么下载器在绑定时需要使用用户设置的快捷键。
- 下载器会在一些按钮上显示快捷键提示，默认显示的是内置的快捷键。如果用户修改了快捷键，就需要能显示用户设置的快捷键。这些提示先不用处理，等实现了自定义快捷键功能之后再处理。

## 一级快捷键列表

现在有 9 个一级快捷键：

| 快捷键  | 功能               | 注册该快捷键的模块                          | 生效的页面       | description                    |
| ------- | ------------------ | ------------------------------------------- | ---------------- | ------------------------------ |
| Alt + X | 切换显示设置面板   | src\ts\setting\SettingsPanelShell.ts        | 所有页面         | 查看/关闭设置面板             |
| Alt + Z | 点击默认的抓取按钮 | src\ts\setting\SettingsPanelShell.ts        | 所有页面         | 点击默认的抓取按钮（开始抓取） |
| L       | 切换显示日志区域   | src\ts\ShowLogButton.ts                     | 所有页面         | 查看/关闭日志区域             |
| Alt + S | 手动选择作品       | src\ts\SelectWork.ts                        | 所有页面         | 手动选择作品     |
| Alt + W | 手动排除作品       | src\ts\ExcludeWork.ts                       | 所有页面         | 手动排除作品     |
| Alt + P | 切换预览作品功能   | src\ts\PreviewWork.ts                       | 所有页面         | 启用/关闭预览作品功能         |
| Alt + Q | 快速下载作品       | src\ts\crawlMixedPage\QuickCrawl.ts         | 仅在作品页面生效 | 在作品页面里，快速下载当前作品 |
| Alt + B | 快速收藏作品       | src\ts\pageFunciton\QuickBookmark.ts        | 仅在作品页面生效 | 在作品页面里，快速收藏当前作品 |
| Alt + C | 复制作品信息       | src\ts\pageFunciton\CopyButtonOnWorkPage.ts | 仅在作品页面生效 | 复制作品的图片和摘要信息       |

其中 `L` 不处理，因为扩展设置里的快捷键必须以 Ctrl 或 Alt 开头，不能直接使用单个字母。所以 `L` 保持现状，不处理。

在剩下的 8 个快捷键里，由于 Chrome 最多只能预设 4 个默认快捷键，因此这 4 个作为在 manifest 里预设的快捷键：
- Alt + X
- Alt + Z
- Alt + S
- Alt + E（这个快捷键被 Chrome 保留所以无法作为预设快捷键，改为了 Alt + W）

这 8 个快捷键都允许用户在扩展设置里自定义快捷键。

备注：
- 如果在 manifest 里预设了超过 4 个快捷键，那么 Chrome 会报错：Too many shortcuts specified for 'commands': The maximum is 4.
- 浏览器没有限制可以自定义的快捷键数量。
- Chrome 扩展 suggested_key 要避免的保留组合包括：Alt+E/Alt+F（菜单）、Alt+D（地址栏）、Ctrl+Shift+J/I/C（开发者工具）、Ctrl+N/T/W、Ctrl+Shift+B/O、Ctrl+H/J/P/S、Ctrl+Shift+Delete、功能键 F5/F11/F6、Ctrl+Tab，以及任意 Ctrl+Alt+* 组合（Chrome 整个禁用，避免与 AltGr 冲突）。

另外，Alt + C 既是一级快捷键，也是二级快捷键。它在作品页面里是一级快捷键，同时当某些功能启用时，是二级快捷键。由于它在作为一级和二级快捷键时，功能含义是相同的，所以如果用户修改了这些快捷键，那么修改对一级和二级都生效。

## 可行性分析

### 结论

可以使用 WebExtension 的 `commands` 机制实现，并且 Chrome、Firefox 都支持 Manifest V3 中的 `commands` 和 `commands.onCommand`。现有的 8 个可配置一级快捷键可以迁移；`L` 按需求保持现状，不纳入这套机制。Chrome 仍限制扩展最多预设 4 个默认快捷键。

建议将“快捷键”与“功能动作”解耦。浏览器负责把用户实际配置的按键映射为稳定的命令名；下载器只根据命令名执行对应动作。这样用户改键后，不需要把按键字符串同步到下载器的设置中，也不需要让每个模块自行解析 `KeyboardEvent`。

### 浏览器机制与兼容性

- 在 `src/manifest.json` 中增加 `commands`。每个一级功能使用固定命令名，例如 `toggle-settings-panel`、`start-default-crawl`、`toggle-log`。每个命令的 `description` 会显示在浏览器的快捷键管理界面，应使用现有的 manifest i18n 机制提供多语言文本。
- service worker 通过 `browser.commands.onCommand` 接收命令。回调参数包含命令名和触发时的活动标签页；应把命令消息发送到该标签页的内容脚本。若标签页不是下载器已注入的 Pixiv / Pixivision 页面，发送失败时应忽略，不应产生未处理的 Promise rejection。
- 内容脚本收到命令后，通过 `EVT` 分发语义化事件；原来注册快捷键的模块监听该事件，并调用和按钮点击相同的动作方法。命令执行不依赖用户实际使用的按键，所以不受 Chrome / Firefox 显示格式、macOS `Command` 映射等差异影响。
- 用户在 Chrome 的 `chrome://extensions/shortcuts`、Firefox 的“管理扩展快捷键”页面配置按键。浏览器会持久化该配置，下载器不应再把一级快捷键保存到 `Settings`。以后需要在下载器 UI 中显示实际按键时，可由 service worker 调用 `browser.commands.getAll()`，再把结果发送给内容脚本。
- Firefox 支持通过 `commands.update()` 和 `commands.openShortcutSettings()` 修改或打开快捷键设置；Chrome 不支持由扩展以代码修改快捷键。为了保持兼容，第一版不应依赖这两个 API，也不应在下载器的设置面板里提供修改按键的输入框。

### 两项限制

1. `L` 不纳入浏览器命令。Firefox 对普通按键组合要求包含修饰键（功能键除外），而需求明确保持裸 `L` 的现有行为，因此继续由网页内容脚本监听，不能通过扩展快捷键页面自定义。
2. Chrome 虽允许声明多个命令，但最多只能在 manifest 中提供 4 个 `suggested_key` 默认值；其余 4 个可配置命令仍会出现在 `chrome://extensions/shortcuts` 中，用户可以手动设置，但新安装时默认处于未分配状态。Firefox 不存在这个 Chrome 的“最多 4 个预设值”限制。因而无法在两种浏览器中同时为全部 8 个可配置一级快捷键提供自动默认值。

另外，浏览器及操作系统保留的组合键、已经被其他扩展占用的组合键都不会被扩展覆盖。出现冲突时，浏览器可能让该命令没有有效快捷键，用户需要在其快捷键管理界面改为可用组合。

### 推荐实现方案

1. 在 manifest 声明 8 个可配置一级功能的语义化命令。为 Alt + X、Alt + Z、Alt + S、Alt + W 对应的 4 个功能提供 `suggested_key`；Alt + P、Alt + Q、Alt + B、Alt + C 对应的 4 个命令仅声明 `description`，让用户按需在浏览器快捷键管理页设置。默认值应避免 `Ctrl+Alt`，Chrome 会拒绝该组合以避免与 AltGr 冲突。`L` 继续由 `ShowLogButton` 使用网页键盘事件处理。
2. 在 `src/ts/serviceWorker/background.ts` 添加唯一的 `browser.commands.onCommand` 监听器，将命令名转发到触发命令的标签页。不要根据实际快捷键分支，也不要把用户的快捷键写入 `Settings`。
3. 在内容脚本增加统一的命令消息接收和 `EVT` 分发层。为 8 个 command 定义明确的事件名，避免各模块分别注册 `browser.runtime.onMessage`，也避免把浏览器消息耦合到页面 UI。`L` 不经过这条链路。
4. 在 `SettingsPanelShell`、`ShowLogButton`、`SelectWork`、`ExcludeWork`、`PreviewWork`、`QuickCrawl`、`QuickBookmark`、`CopyButtonOnWorkPage` 中，将现有快捷键分支中的动作提取为可复用方法，并同时供按钮点击和新的 `EVT` 监听调用。
5. 移除或停用已经迁移的一级快捷键对应的网页 `keydown` 判断。否则用户改键后，旧组合仍会在网页里生效，无法达到“修改快捷键”的目的。
6. 保持其他二级快捷键的原有 `keydown` 监听不变。`Alt+C` 同时作为一级和二级快捷键，且两种场景的功能含义相同；迁移时应抽取统一的复制动作，并移除二级场景对硬编码 `Alt+C` 的依赖，使浏览器 command 触发的事件在满足预览 / 查看器上下文时执行同一动作。否则用户修改 command 快捷键后，一级功能会改变而二级功能仍只响应旧的 `Alt+C`。`Alt+B` 已经是纯一级快捷键，不再作为上下文冲突项处理。

### 模块接线与风险

| 功能            | 现有实现特点                                  | 迁移时的处理                                                                                |
| --------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 切换设置面板    | `SettingsPanelShell` 已有 action 图标消息处理 | 复用 `toggle()`，新增命令事件即可。                                                         |
| 默认抓取        | 依赖当前页面中默认按钮是否存在                | 抽取“查找并点击默认按钮”的方法，保留不存在时的提示。                                        |
| 显示日志        | 目前是裸 `L`，且会避开输入框                  | 不迁移到 `commands`；继续保留网页 `keydown` 监听和输入框判断。                              |
| 手动选择 / 排除 | 通过控制按钮切换状态                          | 复用按钮点击或抽取切换方法；必须等控制按钮完成初始化。                                      |
| 切换预览功能    | 修改 `settings.PreviewWork` 并显示提示        | 保持 `setSetting()`，以继续触发所有 `settingChange` 监听器。                                |
| 快速下载        | 仅作品 / 小说 / 未列出作品页面可用            | 继续使用 `show` 或页面类型判断，防止在其他页面构造无效作品 ID。                             |
| 快速收藏        | 按钮和作品数据异步初始化                      | 命令触发时必须确认当前作品工具栏、token 和作品数据均已就绪，不能只依赖已创建的空 `button`。 |
| 复制作品信息    | 当前按钮是 `init()` 内的局部变量              | 需要提升为类成员或抽出复制方法，才能让命令事件安全调用。                                    |

`commands.onCommand` 可能在内容脚本尚未加载完成、页面正在切换，或当前标签页没有下载器内容脚本时触发。service worker 转发消息应捕获失败；内容端各动作也应自行检查页面类型和 UI 初始化状态。对于未就绪的情况，建议忽略这一次命令，不缓存或延迟重放，以免命令在用户已经切换页面后错误作用于新页面。

### 决策结果

- `L` 保持现状，不纳入可自定义快捷键。
- 8 个可配置一级快捷键全部声明为浏览器 command；Chrome manifest 预设 Alt + X、Alt + Z、Alt + S、Alt + W，其余 4 个命令由用户在扩展快捷键页面手动设置。
- `Alt + B` 仅作为一级快捷键处理。
- `Alt + C` 的一级和二级功能含义相同，用户修改后两种场景都应使用修改后的快捷键，并共享同一个复制动作实现。
