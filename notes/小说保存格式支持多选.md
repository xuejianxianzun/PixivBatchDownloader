# 小说保存格式支持多选

调研：让「小说保存格式」（`novelSaveAs`）支持同时保存 EPUB 和 TXT。
本文是前期调研与实现方案评估（**未改代码**）。

## 一、结论概览

- **可行性高，难度中低。**
- **有现成的先例**：动图（ugoira）的保存格式**已经是多选**（6 种格式的独立开关），其实现模式可以直接参照：
  1. 「按格式列表逐个生成，前面的**直接下载（旁路）**、最后一个作为**主文件**走正常下载流程」；
  2. 「文件名按实际格式**替换扩展名**」（`Utils.replaceExtension`，已有现成方法）；
  3. 「下载记录只记一个格式」。
- **关键发现**：`result.ext` 对小说**没有深层消费者**（全仓唯一的读取处会被 `settings.novelSaveAs` 覆盖，见下文§2.4）⇒ 「双选时 ext 存 epub」没有任何兼容性风险。
- 最大的注意点：**合并流程的图片资源可能被请求两遍**（无代码级缓存，靠 HTTP 缓存兜底）、**设置迁移**（老值 → 新结构）、**单篇下载时封面独立文件不能被下载两次**。

## 二、现状梳理

### 2.1 `novelSaveAs` 的全部使用点（9 处）

| 位置 | 用途 |
| --- | --- |
| `Settings.ts`（类型 + 默认值） | `novelSaveAs: 'txt' \| 'epub'`，默认 `'epub'` |
| `OptionsHtml.html` | 2 个 radio（EPUB / TXT），`name="novelSaveAs"` |
| `FormSettings.ts` | 归在 `inputFileds.radio` 列表（表单读取/保存） |
| `FormType.d.ts` | `novelSaveAs: RadioNodeList` |
| `FileName.ts` `createFileName()` | 小说文件名里的扩展名（覆盖 `data.ext`） |
| `MergeNovelFileName.ts` `getName()` | 合并文件名的 `{ext}` 占位符 |
| `MergeNovel.ts`（4 处） | ① `logMergeStart`：选 txt 时提示推荐 EPUB；② `mergeByFormat`：txt / epub 分支选择；③ `downloadSeriesCoverFile`：只有 txt 时才加下载间隔；④ `saveMergedNovelDownloadRecords`：下载记录的文件名扩展名 |
| `Download.ts` `getNovelFileURL()` | 单篇下载分派：`=== 'epub' ? 'makeEPUB' : 'makeTXT'` |
| `SaveNovelData.ts` | 抓取结果的 `ext: settings.novelSaveAs`（注释已说明「这里的 ext 并不重要，下载时会根据 novelSaveAs 设置自动生成」） |

### 2.2 两条下载路径

**单篇（`Download.ts` → `MakeSingleNovelFile.ts`）**
```
Download.download()
  ├─ _fileName = fileName.createFileName(result)        // 含扩展名
  ├─ getNovelFileURL(novelMeta, _fileName)              // 按 novelSaveAs 调 makeEPUB / makeTXT
  │    └─ make 方法内部：下载独立封面文件、处理正文、返回 Blob
  ├─ setProgressBar(_fileName, size, size)
  └─ sendDownload(blob, blobUrl, _fileName, id, batch)  // reply=true，等后台回执 → 状态/记录
```

**合并（`MergeNovel.ts`）**
```
merge()
  ├─ 数据获取（getNovelIds / getAllNovelData / loadGlossaryData / loadSeriesData）← 共享，只跑一次
  ├─ novelName = mergeNovelFileName.getName(...)        // 含 {ext}
  ├─ mergeByFormat(body)
  │    ├─ mergeTXT()  → downloadTXTAssets（内嵌图片、设定资料图片作为独立文件）→ SendDownload.noReply
  │    └─ mergeEPUB() → 图片嵌入 EPUB、逐篇添加 → saveEPUBFile → SendDownload.noReply
  └─ downloadSeriesCoverFile() → 系列封面作为独立图片文件
```

### 2.3 现成先例：动图多格式（`Download.ts` 的 `convertUgoira`）

- 设置：6 个独立 boolean（`ugoiraSaveAsZIP` / `...WebP` / `...WebM` / `...GIF` / `...APNG` / `...Ugoira`），UI 是 checkbox 组（`OptionsHtml.html` 中 `class="need_beautify checkbox_common"`）。
- 处理（`convertUgoira`）：
  - 组装 `needConvertFormats` 数组（**数组顺序有优先级含义**）；
  - 循环处理每种格式：`const newFileName = Utils.replaceExtension(fileName, '.' + format)` 生成该格式的文件名；
  - **非最后一个格式**：`sendDownload(file, url, newFileName, id, -1, false)`——直接下载、「不等待回执」（`reply=false` → `'no_reply'`），**不影响下载状态**；
  - **最后一个格式**：作为返回值交给调用方，走正常的 `sendDownload`（reply=true → 更新状态、写下载记录）。
- 「最后一个格式」的注释结论：*「只有最后 push 的那个会保存下载记录，所以在这个作品的下载记录里，文件名的扩展名就是最后保存的格式」*。

### 2.4 `result.ext` 的消费者调查（回答主人的疑问）

全仓搜索 `.ext`（含 `data.ext` / `result.ext`）只有一处读取：

```ts
// FileName.ts
let ext = data.ext
// 处理小说的扩展名
if (data.type === 3) {
  ext = settings.novelSaveAs    // ← 小说场景被设置值覆盖
}
```

⇒ **小说的 `result.ext` 目前是「死数据」**：除导出/导入的 JSON 里可见之外，下载（命名、去重、记录）全部走 `settings.novelSaveAs`。
**结论：「双选时 ext 存 epub（默认格式）」完全可行，不需要数组。**（详见 §3.6）

## 三、推荐方案

### 3.1 设置结构：拆成 2 个 boolean（对齐动图）

- 新键：`novelSaveAsEPUB: boolean`、`novelSaveAsTXT: boolean`（默认：EPUB = true，TXT = false）。
- 好处：**完全复用**现有表单机制（checkbox 列表、`HTMLInputElement` 类型、`saveCheckBox` / `restoreBoolean`），零新机制；与动图 6 个 boolean 的现状完全同型。
- UI：radio 组 → 2 个 checkbox（HTML 结构直接参照 `ugoiraSaveAs*` 的写法）。
- **老值迁移**：在 `ConvertOldSettings` 增加特殊迁移（参照 `convertExcludeTag` 的先例）：
  - 旧值 `novelSaveAs: 'epub'` → `novelSaveAsEPUB = true`；
  - 旧值 `novelSaveAs: 'txt'` → `novelSaveAsTXT = true`；
  - 处理完删除旧键。兼容「导入的配置文件」与「本地存储」。

对比方案（不推荐）：保持一个键、值改数组（如 `['epub','txt']`）——需要新的「checkbox 组 → 数组」表单机制 + `Settings` 类型/恢复逻辑改造，成本更高、先例更少。

### 3.2 新增模块：格式列表（`src/ts/download/NovelSaveFormat.ts`）

```ts
/** 小说保存格式 */
export type NovelSaveFormat = 'epub' | 'txt'

/** 读取用户选择的小说保存格式（派生设置项）。
 * 修复 / 维护注意：不要绕过本模块直接读 novelSaveAsEPUB / novelSaveAsTXT。 */
class NovelSaveFormat {
  /** 返回要使用的格式列表，至少一项。固定顺序：epub 在前 */
  public getFormats(): NovelSaveFormat[] {
    const formats: NovelSaveFormat[] = []
    if (settings.novelSaveAsEPUB) formats.push('epub')
    if (settings.novelSaveAsTXT) formats.push('txt')
    // 用户可能取消勾选全部；兜底为 epub，保证「至少保存一种格式」
    return formats.length > 0 ? formats : ['epub']
  }

  /** 返回默认格式（= 格式列表第一项 = epub 优先）。
   * 用于：抓取结果的 ext、文件名生成时的扩展名基准、下载记录的扩展名。 */
  public getDefaultFormat(): NovelSaveFormat {
    return this.getFormats()[0]
  }
}

const novelSaveFormat = new NovelSaveFormat()
export { novelSaveFormat }
```

- **落点依据**：与 `EPUBSetting.ts`（同样是「派生设置项」小模块、放 `download/` 目录、import Settings）同型——项目对这类逻辑的既定位置。
- **消费点清单**（全部替换对设置的直接读取）：
  1. `SaveNovelData.ts`：`ext: getDefaultFormat()`
  2. `FileName.ts`：`ext = getDefaultFormat()`
  3. `MergeNovelFileName.ts`：`{ext}` = `getDefaultFormat()`
  4. `Download.ts` `getNovelFileURL()`：按 `getFormats()` 生成 1~2 个文件（见 §3.3）
  5. `MergeNovel.ts`：`mergeByFormat` 等 4 处（见 §3.4）
  6. `DownloadRecord` 无需改动（它经 `fileName.createFileName()` 取默认扩展名）

### 3.3 单篇下载改造（`Download.ts` + `MakeSingleNovelFile.ts`）

思路：**复刻 `convertUgoira` 的主/旁路模式**。

- `download()` 的小说分支：
  - 取得 `formats = getFormats()`；
  - 顺序处理：**非主格式旁路、主格式最后**（主文件走现有的正常流程，使状态/进度/下载记录都记在主文件上）；
    - 主格式建议 = `getDefaultFormat()`（epub 优先），与 `ext`、下载记录、推荐提示的取向一致；
    - 实际处理顺序 = 先 `txt`（若选）旁路下载，最后 `epub`（若选）作为主文件返回（若只选 txt，则 txt 即主文件，行为与现在完全一致）。
  - 旁路下载：`sendDownload(blob, blobUrl, txtFileName, id, -1, false)` + `setProgressBar(txtFileName, size, size)`（复刻动图写法）。
- `MakeSingleNovelFile.ts`：
  - `makeTXT` / `makeEPUB` 已互相独立，**基本不用改**；
  - ⚠️ **必须处理：封面独立文件会被下载两次**——`makeTXT` 和 `makeEPUB` **都**会调 `downloadCover()`（都产出名为 `xxx.jpg` 的独立封面文件），双格式时会产生**同名重复文件**（浏览器会存成 `xxx (1).jpg`）。解决方向：只在其中一个格式的流程里下载独立封面（例如给 make 方法加一个「是否下载独立封面文件」的参数，由调用方决定只下一次；或把封面下载移到 `download()` 里统一处理）。
  - 内嵌图片无此问题：只有 TXT 流程产出独立文件（EPUB 的图片是嵌进电子书的）。

### 3.4 合并下载改造（`MergeNovel.ts`）

- `mergeByFormat()`：`if/else` → **遍历 `getFormats()`**（逐格式执行 `mergeTXT()` / `mergeEPUB()`）。
  - 好消息：**数据获取阶段（获取小说列表/数据/设定资料/系列数据）只跑一次**，双格式的额外成本只在「生成 + 下载」阶段（加上图片可能请求两遍，见下）。
- 相关 4 处条件更新：
  1. `logMergeStart`：`novelSaveAs === 'txt'` 才提示推荐 EPUB → 改为「**格式列表不含 epub** 时提示」；
  2. `downloadSeriesCoverFile` 的等待间隔：`=== 'txt'` 才 sleep → 改为「**不含 epub** 时才 sleep」（含 epub 时封面已在 EPUB 流程加载过，可借 HTTP 缓存直接下载）；
  3. `saveMergedNovelDownloadRecords`：`n: id-title.${settings.novelSaveAs}` → 用 `getDefaultFormat()`（与 §3.6 的 ext 语义一致）；
  4. （顺带）`mergeTXT` / `mergeEPUB` 内部的其它 txt 条件检查一遍（目前只有上述几处）。
- 图片资源会被请求两遍：`DownloadNovelEmbeddedImage` / `DownloadNovelGlossaryImage` / `DownloadNovelCover` **都没有代码级缓存**（每次 `fetch`），双格式时两套流程各自请求一遍封面/内嵌图片/设定资料图片。**HTTP 缓存可部分兜底**（第二次多半命中）。首版建议接受，不专门做「下载一次、两个格式共享」的优化（实现复杂、收益有限）。

### 3.5 文件名适配（`FileName.ts` / `MergeNovelFileName.ts`）

- 两个模块继续生成**含「默认格式」扩展名**的文件名（`getDefaultFormat()`）——保持「一次生成、单一基准」；
- 实际保存每种格式时，用**现成工具 `Utils.replaceExtension(name, '.' + format)` 替换扩展名**（与动图 `convertUgoira` 中的用法完全一致）：
  - 单篇：`fileName.createFileName(result)` 生成 `xxx.epub` → 旁路的 txt 文件用 `Utils.replaceExtension(_fileName, '.txt')`；
  - 合并：`mergeNovelFileName.getName()` 生成 `xxx.epub` → txt 版本替换为 `xxx.txt`（注意 `part` 参数（分卷编号）由 `getName` 生成，替换扩展名不影响）。
- 一个无碍的小细节：扩展名长度参与「文件名长度限制」计算（`.epub` 5 字符 / `.txt` 4 字符），以默认格式生成、替换后目标格式的文件名最多差 1 个字符，边缘情况影响极小（且 `replaceExtension` 只替换「最后一个点」之后的部分，不改变主体长度）。

### 3.6 `ext` 的处理（结论）

- **维持单值，值 = `getDefaultFormat()`（双选时 = epub）**——即主人的方案。理由：
  1. 小说的 `result.ext` 没有深层消费者（§2.4 调查）——不会与「实际保存了两种格式」产生任何矛盾；
  2. 所有「真正使用扩展名」的环节（文件名、下载记录、去重、命名规则里的 `{ext}`、合并文件名）都是**运行时重新计算**的，不依赖 `result.ext`。
- 备选（不建议）：存数组或逗号串（`'epub,txt'`）——要改类型和所有读取方，收益为零。

## 七、实施记录（2026-10-13）

**已按本方案实施并通过实机测试。** 落实说明与方案的两处差异：

### 7.1 设置迁移改用「ugoiraSaveAs 同款模式」

实施时发现了比「ConvertOldSettings 特殊迁移」更贴合的先例：动图的 `ugoiraSaveAs`（旧单选 → 6 个新 boolean）的迁移直接在 `Settings.setSetting()` 里处理，且默认设置里**保留旧键**（注释「该设置仅为保留兼容性而存在」）。小说格式照此处理（不需要动 `ConvertOldSettings.ts`）：

```ts
// setSetting 内
if (key === 'novelSaveAs') {
  this.settings.novelSaveAsEPUB = value === 'epub'
  this.settings.novelSaveAsTXT = value === 'txt'
}
```

⚠️ **关键不变量**：`defaultSettings` 里旧键 `novelSaveAs` 必须放在两个新键**之前**。遍历设置时旧键先迁移、新键的值（若存储里存在）随后覆盖它——这样用户在新版本里修改的选择永远不会被旧键覆盖。

**关于「旧键会一直保留、迁移每次初始化都执行」**（机制说明）：

- 旧键 `novelSaveAs` **会永久留在设置里**：保存时写的是整个 `this.settings` 对象（含旧键），而初始化过程本身就会触发保存（每个 `setSetting` 末尾 fire `settingChange` → 监听器调用 `store()` debounce 50ms 后写盘），所以旧键只会被不断写回；
- 迁移代码**每次初始化都会执行**（只要旧键在存储里）：`restore()` → `assignSettings(存储数据)` → `Object.entries` 遍历遇到旧键就执行；
- **为什么无害**：键序不变量（同上）+ 迁移幂等；用户在新版本里的选择由「后处理的新键值」胜出，反复初始化结果稳定（已用模拟脚本验证 4 个场景）。与 `ugoiraSaveAs` 先例完全同构；
- 🔴 **旧键不能删**：`setSetting` 开头会检查 `allSettingKeys.includes(key)`（= `defaultSettings` 的键），不在其中就直接 `return`——如果从 `defaultSettings` 删掉旧键，**导入旧版本导出的设置文件时将无法迁移**（旧值被丢弃，用户的格式选择会回落到默认的 epub）。这也是 `ugoiraSaveAs` 必须保留的原因。
