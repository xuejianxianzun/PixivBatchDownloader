# 为选择作品的功能添加框选功能

我想为“手动选择作品”和“手动排除作品”添加框选功能。现在当用户启用这两个功能（状态）之后，会在鼠标光标处显示一个圆形的指示器。有些用户以为能像文件管理器那样框选，但实际上不能。我想让你添加这个功能，目前我的设想：

- 不能与点击（单击）作品的动作冲突，因为单击会选择/排除作品
- 框选操作以“按住并移动”启动，不需要先长按等待：按下（鼠标左键 / 单指触摸）后移动超过一定距离即进入框选，松开结束。手感应该像平时选择文本、选择文件那样直接
- 按住并移动默认会触发浏览器自己的选择操作（如选中页面上的文本），因此在处于手动选择/排除状态中时，需要阻止浏览器默认的选择操作
- 在某些元素上按住拖动还会触发浏览器原生的拖拽操作，也需要阻止默认的拖拽操作
- 框选过程中，如果鼠标移动到页面顶部/底部，则让页面滚动以便可以实现连续框选。此功能可能需要评估复杂度
- 在框选范围内查找作品时，只查找有 `.ppd-workThumbnail` 的元素，这是 src/ts/WorkThumbnail.ts 模块已经查找到的的作品缩略图
- 如果按下的位置在作品（也就是 `.ppd-workThumbnail` 元素）上，之后移动了鼠标，则取消默认的拖拽动作（同上），并让框选正常进行（框选范围会自然包含这个作品）
- 如果按下后没有移动（或移动距离很小），则不执行框选，按原有的单击逻辑处理。在移动端的事件里，需要能识别触摸是否发生了移动（如果 touch 范围变化很小，则不应视为移动）
- 不使用 js 库，自行实现即可

### 关键事实

1. **单击链路（框选不能破坏它）**：
   - PC：缩略图元素上的 `click` → `clickThumbnail()`；`document.body` 捕获阶段的 `click` → `clickElement()`。两者识别为作品后都会 `preventDefault + stopPropagation`，把「点击作品」变成选择/排除（不进入作品页）。
   - 移动端：对应事件是 `touchend`，两处 handler 都先检查 `tapDetector.isTap()`，位移 > 10px 的手势直接跳过。
2. **拖动结束后误触点击的风险与现状**：
   - 移动端：已被 `tapDetector` 天然拦截（位移 > 10px → `isTap()` 为 false，两处点击 handler 都会跳过）。因此框选拖动（>10px）结束后不会误触发点击。
   - PC：没有任何保护。拖动 ≥ 10px 后若 `mouseup` 正好落在缩略图（或链接）上，浏览器仍会派发一次 `click` → 会误 toggle 作品。**框选模块必须自己拦截这一次 click**（见设计第 3 节）。
3. **可框选的条件**：`canSelect() / canExclude()`（模式已激活且未暂停）、页面不在 `disablePageList`（目前只有 `Unlisted`）、设置面板未打开（`tempHide`）。目前这两个方法是 private，新模块需要读取这些状态（改为 public 或使用等价的状态判断）。
4. **`.ppd-workThumbnail` 的数据**：`data-workid` / `data-worktype`；小说/系列小说在回调里用 `Tools.getNovelOrSeriesIDData()` 重新解析；系列标题用 `Tools.getSeriesTitleFromElement()`。
5. **「仅添加」的现成语义**：`selectAll()` 用 `workSelection.addSelectId()`（不反选）。框选建议同样采用「仅添加」，避免把已选作品 toggle 掉。
6. **单击是 toggle**：`addId()` 走 `toggleSelectId()` / `toggleExcludeId()`（可反选）。框选应与它不同。
7. **排除动作的额外处理**：`ExcludeWork.addId()` 还会在无下载任务时 `store.removeWorkById()`——框选批量添加时同样需要这段逻辑。
8. **一个作品可能有多个缩略图**：`addSelectedFlag()` 会为同 id 的所有缩略图补标记，框选无需处理。
9. **自动滚动的物理限制**：pixiv 搜索页是分页、无滚动加载（项目备忘）；滚动目标以 `window` 为准。
10. **浏览器默认行为（本次要处理的新问题）**：
    - 按住拖动默认会触发文本选择（`selectstart`，可 `preventDefault()` 阻止）；
    - 图片（`img`）、链接（`a`）等元素默认可拖拽，按住拖动会触发 `dragstart`（可 `preventDefault()` 阻止）；
    - 项目里目前没有针对这两类事件的防御（只有 `ShowOriginSizeImage` 对鼠标右键的 `contextmenu` 做过一次性屏蔽，互不冲突）；
    - 搜索框等输入元素（`input` / `textarea` / `[contenteditable]`）不应受影响，阻止选择时必须排除它们。
11. **移动端与滚动的手势冲突（本次方案变化引入的核心问题）**：
    - 移动端「单指按住拖动」是浏览器用于滚动页面的系统手势。如果框选也在单指拖动时启动，用户将无法滚动页面 ⇒ 移动端不能无差别地「按下即框选」。
    - 桌面端没有这个问题（鼠标拖动不承担滚动职责），可以「按下即框选」。
    - 移动端方案：已拍板采用「长按后拖动」（见「四、已拍板的决定」）。

## 二、实现方式：不使用第三方库

不使用 js 库，自行实现。核心逻辑（手势判别、框选矩形、命中检测、自动滚动）没有难以实现的部分，自研可以精确控制与「单击选择/排除」的配合、阻止浏览器默认行为的时机、以及与项目标记系统的集成。与项目一贯做法一致（`Utils.longPress`、`TapDetector` 都是自研）。

## 三、设计议案（暂定新模块 `src/ts/WorkSelectionMarquee.ts`）

### 1. 手势判别

桌面端（鼠标左键）：

```
idle ──左键按下──▶ pressing ──位移 > 10px──▶ dragging ──松开──▶ 提交框选
   ▲                  │                       │
   │                  └──松开（位移 ≤ 10px）──▶ 不框选，click 正常触发（单击选择/排除作品）
   └──────────────取消（失焦 / 页面切换 / 模式变化等）─────────────┘
```

- **不需要长按等待**：按下即进入 pressing，位移一超过阈值（10px，与 TapDetector 一致）立即进入框选，手感与「选择文本 / 选择文件」一致。
- 只响应鼠标左键（`button === 0`）；按住不动不设超时，随时可开始拖动。
- 位移 ≤ 10px 就松开：不视为框选，完全交给原有 click 链路（单击选择/排除）。
- 按下目标为输入类元素时跳过（不启动）。
- 取消条件：窗口失焦、页面切换（`pageSwitch`）、模式被切换/暂停、Esc。
- 兜底：拖出窗口导致 `mouseup` 丢失的极端情况——`window` 失焦时取消；下一次 `mousedown` 时重置残留状态。

移动端（单指触摸）：采用「长按后拖动」启动框选（已拍板）。流程为：

```
idle ──单指按下──▶ pressing ──500ms 未大幅移动──▶ armed ──位移 > 10px──▶ dragging ──松开──▶ 提交
   ▲                  │                            │
   │                  └──位移 > 10px──▶ 取消（让浏览器正常滚动页面）
   │                                               └──松开（未移动）──▶ 不框选，抑制本次点击
   └──取消（多指触摸 / touchcancel / 模式变化等）────────────────────────┘
```

- 与滚动的分工：短按后直接滑动 = 滚动页面（照旧）；长按 500ms 后滑动 = 框选。
- 关键常量：位移阈值 10px（桌面/移动统一，与 `TapDetector` 一致）；长按 500ms（仅移动端使用，与 `longPress` 默认值一致）。

### 2. 阻止浏览器默认行为

对应设想中的两条要求（阻止默认的选择操作、阻止默认的拖拽操作）。分两种时机：

a. **文本选择 —— 模式激活期间全程阻止**：监听 `selectstart`（document，捕获阶段），当选择/排除模式处于活动状态时 `preventDefault()`。
   - 这同时覆盖了双击选词、三击选段、Ctrl+A 等所有文本选择途径——模式激活时页面文本不再可被选择（这正是需求；需要选中文本时可先按 Esc 暂停模式）。
   - 排除输入类元素（在 `input` / `textarea` / `[contenteditable]` 上放行），搜索框等仍可正常使用。
b. **原生拖拽 —— 模式激活期间全程阻止**：监听 `dragstart`（document，捕获阶段），模式激活时 `preventDefault()`。覆盖作品图片、超链接等元素的原生拖拽。
   - `dragstart` 被阻止后原生拖拽不会启动，鼠标移动事件照常派发，框选不受影响。
c. **触摸滚动 —— 仅框选手势期间（移动端）**：进入 armed / dragging 后，`touchmove` 需 `preventDefault()` 阻止页面滚动；监听器必须显式 `{ passive: false }`（Chrome 对 document 级 touchmove 默认 passive）。pressing 阶段不阻止——此时若位移超阈值会取消框选、让浏览器正常滚动。
d. **上下文菜单 —— 仅移动端、触摸进行中**：Android Chrome 长按约 500ms 会弹上下文菜单，可能打断「长按后拖动」；因此在移动端、模式激活且有活动触摸（pressing / armed / dragging）时阻止 `contextmenu`。（桌面端鼠标右键菜单不受影响。）
e. 双保险：进入 dragging 后给 `<html>` 加一个临时 class（`user-select: none`），结束/取消时移除。

两点说明：

- 为什么阻止时机是「模式激活期间」而不是「手势进行中」：拖动的第一像素就可能触发选择/拖拽，没有「长按成功」这种明确的提前时机，因此守卫必须覆盖整个模式激活期。（旧方案是长按启动，可以从长按成功后才开始阻止；新方案必须提前。）
- 不使用 `mousedown` 的 `preventDefault()`：副作用较大（会阻止输入框获取焦点等），精确阻止 `selectstart` / `dragstart` 已经足够。

### 3. 拖动结束后的 click 拦截（桌面端）

背景见「关键事实 2」：PC 上拖动 ≥ 10px 后，若 `mouseup` 落在原缩略图/链接上，浏览器仍会派发一次 `click`，不拦截就会误 toggle 作品。

处理：

- 本次手势进入过 dragging 时，在结束（mouseup）时设置一次性标记；
- `document` 捕获阶段的 `click` 监听发现标记后，`stopPropagation() + preventDefault()`（同时阻止 `clickThumbnail` / `clickElement` 与链接跳转），并清掉标记；
- 下一次 `mousedown` 也重置该标记，保证不会残留到下一次正常点击。

移动端不需要（`tapDetector` 已把位移 > 10px 的手势判为非 tap）。

### 4. 起点在作品上的情况

无需特殊处理，自然成立：

- 从作品上开始拖动时，原生拖拽已被全局 `dragstart` 守卫阻止（第 2 节 b）；
- 框选矩形从按下点开始展开，与该作品必然相交，提交时自然包含它。

### 5. 命中检测与渲染

- 框选矩形用**文档坐标**表示：
  - 起点 = 按下时的 client 坐标 + 当时滚动量；
  - 当前点 = 鼠标当前 client 坐标 + 当前滚动量（自动滚动时随之增长）。
- 渲染：`position: fixed` 的矩形元素，显示坐标 = 文档坐标 − 当前滚动量（滚动时矩形「被页面带着走」的视觉自然成立）。
- 候选元素：`document.querySelectorAll('.ppd-workThumbnail')`，跳过 `checkLI()`；判定 = 元素 rect（文档坐标）与框选矩形**相交**即命中。
- 每帧（rAF 节流）对命中集合做 diff：新进入的加临时高亮 class、离开的移除（松开前缩回框选范围会取消高亮）。
- 松开时：提交**当前**高亮集合（以松开瞬间的矩形为准）→ 移除高亮 → 交给两模块批量添加。
- 提交空集合时静默结束（无提示），避免拖动过程中频繁弹出提示。
- 性能：全量 `getBoundingClientRect` 每帧约 O(N)，N 通常几百；如卡顿可加「元素 rect 缓存 + 滚动时刷新」。

### 6. 自动滚动（复杂度评估：中低）

- 拖动中鼠标进入视口上/下边缘 50px 内 → 启动 rAF 循环 `window.scrollBy(0, speed)`；
- 速度随离边缘的距离增大（建议最高 ≈ 20px/帧）；
- 滚动期间照常更新矩形与命中检测；鼠标离开边缘或松开 → 停止；
- 兜底：滚到顶/底时 `scrollBy` 自然无效；`pageSwitch` 时终止。
- 合计约 60 行，无外部依赖。

### 7. 与现有模块集成

- 新模块在 `src/ts/crawl/InitPageBase.ts` 与 `SelectWork`、`ExcludeWork` 一起副作用 import。
- 提交路径：直接调用两模块新增的 public 方法（如 `selectWork.toggleElements(elements)`）——marquee 与这两个模块本就是一组功能，直接调用更简单直接。
- `SelectWork` / `ExcludeWork` 各新增「批量 toggle」方法（`toggleElements(elements)`）：
  - 复用 `selectAll()` / `addId()` 的相应逻辑（解析 id/type → `workSelection.toggleSelectId() / toggleExcludeId()` → `addSelectedFlag() / removeSelectedFlag()` → 更新按钮 UI）；
  - 提交语义是 **toggle（反选）**：已选择的作品被取消选择，未选择的作品被选中；
  - 同一个 id 可能命中多个缩略图，批量处理前先按 id 去重，避免相互抵消；
  - `ExcludeWork` 的批量处理同样要做「无下载任务时 `store.removeWorkById()`」。
- 需将 `canSelect()` / `canExclude()` 改为 public，供新模块读取状态。

### 8. 移动端细节（长按后拖动）

- 全程支持 touchstart / touchmove / touchend / touchcancel，取消条件增加「多指触摸」。
- 「长按后未移动就松开」：不提交框选，同时**抑制本次 touchend 的点击**——否则会误选/误排除作品（此时 `tapDetector` 会视为轻点）。实现：进入 armed 后设置标记，由 `touchend` 捕获阶段的监听消费。
- 已知挑战与对策：
  - Android Chrome 长按弹菜单 → 第 2 节 d（阻止 contextmenu）；
  - iOS 的 callout（长按图片/链接的弹出菜单）：`-webkit-touch-callout: none` 仅在手势期间添加到 `<html>` 上。

### 9. 视觉与文案

- 框选矩形：新增 less（选择 = `--beautify-blue`、排除 = 红色；半透明填充 + 描边 + `pointer-events: none`）；
- 临时高亮：独立 class（正式标记仍由 `addSelectedFlag()` 添加）；
- 拖动开始时圆点指示器是否隐藏：实现时看效果微调；
- 一次性提示（已拍板要做）：新增两条 langText 文案——`_按住并拖动可以框选作品`（PC）/ `_长按后拖动可以框选作品`（移动端）。
  并入现有的「首次进入模式」提示：与快捷键提示合并为一个弹窗展示、各自独立「只显示一次」；新增 key 必须一次补齐 6 语。

## 四、已拍板的决定（2026-10-12）

1. **移动端**：采用「长按 500ms 后拖动」启动框选（保留单指滚动；需阻止长按弹出的上下文菜单）。
2. **框选提交语义：toggle（反选）**。框选到之前已选择的作品时，会取消它的选择；未选择的作品会被选中。
3. **命中判定**：相交。
4. **拖动过程实时高亮**：要。
5. **Esc 取消当前框选**：支持（手势进行中按 Esc 只取消框选，不影响「Esc = 暂停模式」的原有行为）。
6. **一次性提示**：要（与快捷键提示合并为一个弹窗；PC 与移动端文案不同；各自独立只显示一次）。
7. **移动端长按后未移动就松开**：抑制本次点击（不误选/误排除）。

### 实现中发现并修复的问题

- **提交时可能漏算「最后一刻」的命中**：拖动结束时，最后一次移动之后 rAF 可能还没执行（例如鼠标快速甩动后立刻松手），只用当时的高亮集合会漏掉最后移动的一小段。修复：`finish()` 里先按当前矩形同步更新一次命中，再提交。此问题由实机测试发现（测试用例：mousemove 与 mouseup 同帧连发）。

### 测试结果（摘要）

- **PC（鼠标路径）**：单击正常；未超阈值不框选；框选矩形位置精确、高亮与预期完全一致；toggle 反选正确（已选作品被取消、未选作品被选中、再框选恢复）；拖动结束后拦截 click（探针验证）；`selectstart` / `dragstart` 在模式激活时阻止、暂停时放行；Esc 在手势中只取消手势（不触发暂停模式）。
- **移动端（触摸路径，模拟 iPhone 环境）**：长按 600ms 后拖动框选成功（过程中 `touchmove` 的 `preventDefault` 逐步生效，阻止页面滚动）；长按不动就松开时不误选（touchend 被抑制）；长按未达门槛就移动时取消框选且不阻止 `touchmove`；长按期间阻止 `contextmenu`（用监听器探针确证：非手势时我们的监听器不阻止，「非手势时被阻止」是页面自身/其他扩展的环境性行为）。
- 静态检查：`npm run ts` 通过、prettier 通过、`node --test` 155 项全部通过（含新增 `tests/marquee-math.test.cjs` 7 项，并做了反向验证——临时破坏函数确认断言会失败）。
