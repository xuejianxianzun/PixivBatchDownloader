# 命名规则里的可选片段

目的：当命名规则中的标记没有值时，忽略其附近的自定义字符。

方式：使用 `[]` 包裹一个标记以及与它相关的字符，作为可选片段。当这个标记的值为空时，忽略整个片段。

## 对命名规则系统的说明

下载器有“命名规则”设置，用来设置文件夹和文件的名字。下面是一些说明：

`src\ts\FileName.ts` 负责根据命名规则生成文件夹和文件名。

一个命名规则可以由 3 部分组成：
- 特殊标记，例如 {id}、{user}、{title} 等，每个标记都可能会输出一些字符。标记的含义在下面有说明。
- 斜线 / 用来建立文件夹。每个斜线前面的内容都是文件夹的名字，最后一个斜线之后的部分是文件名。你可以添加多层文件夹，也可以自由的组织文件夹结构。
- 普通字符和符号。你可以在标记之间添加普通字符，例如 pixiv/{id}-title {title}-user {user}

建立文件夹的说明：
- 如果你想为每个作品建立一层文件夹，可以在文件名前面添加一层文件夹。使用作品 ID {pid} 作为文件夹名字是一个通用的选择，例如 pixiv/{user}/{pid}/{id}。当然你也可以根据自己的需要使用对应的标记。
- 如果你想把 AI 生成的作品放到单独的文件夹里，可以使用 {AI} 标记，例如：pixiv/{user}/{AI}/{id}
- 如果你想根据作品类型建立文件夹，可以使用 {type} 标记，例如：pixiv/{user}/{type}/{id}

提示：
- * 有些标记并不总是可用，有时它们会是空字符串，下载器会忽略它们。

由于用户可以添加自定义文字，这些文字经常与前方或后方的命名标记有关联，例如：
- `user {user}` 前面的 user 是说明性文字
- `{pid}-{p}-{title}` 有些标记后面有横线 -，用于分割相邻的命名标记，用来区分不同标记生成的内容，避免它们直接挨在一起无法区分。

## 使用 [] 建立可选片段，当标记为空时忽略其中的所有内容

要解决的问题：一些标记可能输出空字符串，此时它没有内容，但与之相关的自定义文字却会依然保留，这导致用户体验不佳。例如：
- `serise：{series_id}`：当 `{series_id}` 为空时，会留下不需要的 `serise：` 字符
- `{pid}-{p}-{title}`：当 `{p}` 为空时，其后的横线会留下，导致这个片段变成了 `{pid}--{title}`，多了一个不需要的横线。对于这种情况，我已经添加了 `removeEmptyTag` 方法来移除不需要的单个符号，但仍然有很多情况没有覆盖到。

为了解决这个问题，需要一种易于使用（对用户来说复杂度不高）的方式，让用户能够去除不需要的字符。

有一位用户提出了使用 `[]` 包裹“自定义字符+标记”的方式，例如 `[serise：{series_id}]`。在生成文件名时，处理每个 `[]`  包裹的内容，如果其中含有标记，且标记为空，那么就忽略整个 `[]` 里的内容，这样就可以去掉自定义字符。

我想让你帮我在 `generateFileName` 方法里实现这个处理措施。应该在第一个 `for of` 循环之前添加一个函数来处理这部分逻辑，因为第一个 `for of` 循环会把命名标记替换成实际的值，而这个逻辑需要对值为空的标记进行特殊处理，所以应该先行处理。

实现时的具体逻辑的说明：
1. 需要在“把命名标记替换为实际值之前”之前先处理可选片段，否则无法判断片段里的标记是否为空。
2. 我打算让用户在一个 `[]` 片段里只包含一个可能为空的标记，例如  `[{p}-]`。但用户可能不按规范来，所以如果一个 `[]` 片段里包含了多个标记（如 `[prefix-{p}-{title}]`），则不处理这个片段里的内容，以避免误删。
3. 如果一个 `[]` 片段里包含至少一个命名标记，那么不管这些标记是否有值，都需要去掉 `[]` 符号本身，因为此时它们是有特殊含义的符号，不是文件名结果的一部分。
4. 如果一个 `[]` 片段里没有包含任何标记，则不处理这个片段。此时把 `[]` 符号原样保留，因为它们在这种情况里无法实现设计目的（这可能是用户有意为之的，即用户想原样使用 `[]` 符号），因此把它们视为普通字符保留。
5. 可能存在未闭合的 `[]`，即只有 `[` 却没有 `]`，或者相反，不处理这些片段。只处理闭合的 `[]`。
6. 用户可能使用嵌套的 `[]`，例如 `[[{p}-]]`。这种情况保留外层的 `[]`，把外层的 `[]` 视为普通字符保留（视为文件名结果的一部分）；只处理最内侧的 `[]` 片段，并把内层的 `[]` 视为有特殊含义的符号给去掉。
7. 可选片段里可以使用文件夹路径（即 `/` 符号），该符号不需要特殊处理。

## 测试用例

我构造了一个测试用的命名规则：

```
pixiv/[页面标签：{p_tag}/][serise：{series_id}]-{user}/{r18_g_folder}/[{abc}-][[order：{series_order}]]-user：[{user_id}-]{id}-[sl：{sl}[-{p}][-{title}-{rank}]
```

包含了：
- 标准情况：`[serise：{series_id}]` 和 `[-{p}]`
- 含文件夹斜线：`[页面标签：{p_tag}/]`
- 会被替换成其他命名规则：`{r18_g_folder}` 会被替换成 `[R-18&R-18G]`
- 假的命名标记：`[{abc}-]`
- 双层嵌套：`[[order：{series_order}]]`
- 内含多个标记：`[-{title}-{rank}]`
- 未闭合的标记：`[sl：{sl}`
- 故意留在外面的横线：`{series_id}` 可能为空，其后的横线故意没有包裹在方括号里

测试环境：在图像作品页面里进行下载，这些标记的值是空字符串：
- `{p_tag}`
- `{series_id}`
- `{series_order}`
- `{rank}`

预期执行结果：
```
pixiv/-<user>/[R-18&R-18G]/[{abc}-][]-user：<user_id>-<id>-[sl:<sl>-<p>-<title>
```

各部分的行为如下：

| 测试内容                                           | 实际结果                                                           | 是否符合设计     |
| -------------------------------------------------- | ------------------------------------------------------------------ | ---------------- |
| `[页面标签：{p_tag}/]`，`{p_tag}` 为空             | 整段包括 `/` 被删除                                                | 是               |
| `[serise：{series_id}]`，`{series_id}` 为空        | 整段被删除                                                         | 是               |
| `{r18_g_folder}` 替换为 `[R-18&R-18G]`             | 因其中没有 schema 中的命名标记，`[]` 原样保留                      | 是               |
| `[{abc}-]`                                         | `{abc}` 不是已知命名标记，整个片段原样保留                         | 是               |
| `[[order：{series_order}]]`，`{series_order}` 为空 | 内层删除，外层方括号保留，结果是 `[]`                              | 是，符合嵌套规则 |
| `[-{p}]`，`{p}` 非空                               | 去除 `[]`，结果为 `-<p>`                                           | 是               |
| `[-{title}-{rank}]`，`{rank}` 为空                 | 可选处理只去掉 `[]`；后续既有逻辑删除 `-{rank}`，结果为 `-<title>` | 是               |
| `[sl:{sl}` 未闭合                                  | 开始的 `[` 原样保留，但 `{sl}` 仍走普通标记替换                    | 是               |
| 内部的 `[-{p}]`、`[-{title}-{rank}]`               | 虽然位于未闭合 `[` 之后，但它们自身闭合，仍分别按正常可选片段处理  | 是               |

## 设置面板里的说明文本

有些命名标记在特定情况下可能没有内容。例如，当作品不属于一个系列时，`{series_title}` 就不会输出系列标题。

如果标记旁边还有说明文字或符号，即使标记没有内容，这些字符仍可能保留下来。例如：
- `系列：{series_title}`：当没有系列标题时，会留下 `系列：`
- `{rank}-{id}`：当没有排名时，可能会留下多余的横线 `-`

如果你想忽略不需要的字符，可以创建可选片段。方法是使用 `[]` 包裹一个可能为空的命名标记，以及与它有关的字符。例如：
- `[系列：{series_title}]`
- `[{rank}-]`
- `[-{p}]`

当标记有内容时，下载器会正常输出片段里的内容，但不会输出 `[]`。
当标记没有内容时，下载器会忽略整个片段，所以不会留下多余的字符。

附加说明：
- 只需要对可能为空的命名标记使用可选片段。有些标记始终有内容，例如 `{id}`、`{user}`，不需要使用此功能。
- 每个 `[]` 里只应放 1 个命名标记。不要把多个标记放进同一个片段，这会导致下载器依然保留多余的字符。
- 如果有需要，你可以使用多个可选片段，例如 `[SeriesID={series_id}][ {series_title}]`。
- 如果 `[]` 里没有命名标记，`[]` 会被视为普通字符并原样输出。
- 如果 `[]` 里有命名标记，但你又想在结果里保留 `[]`，可以使用两层 `[]`。例如 `[[{rank}]]` 的结果会像这样 `[1]`。此时内层的 `[]` 用于可选片段，外层的 `[]` 会原样保留。
